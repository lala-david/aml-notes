### 설계는 이런 순서로 시작한다 (일반 절차)

1. **문제 정의·범위**: 사업유형, 상장 자산·체인, 해외 VASP 이전 여부
2. **Gap Analysis**: 현 체계 vs 특금법·업무규정 제76~81조·이용자보호법 §12·통신사기피해환급법·FATF R.15/INR.15 매핑 표
3. **도구 PoC**: 분석 벤더는 귀속 일치율·점수 안정성·커버리지·감사 가능성으로 비교 ([`../notes/4-technology/kyc-kyt.md`](../notes/4-technology/kyc-kyt.md) 💼 PoC 체크리스트)
4. **MVP**: 제재 스크리닝 + 거래모니터링 + STR 워크플로
5. **확장**: 2027-02-19 대비 — 트래블룰 전건화, 해외 VASP 3등급, 자기수탁 동일인 확인, 1천만원 이상 자체 감시체계

### Mini Risk Engine 설계 시 꼭 들어갈 "현실 요소"

- **벤더 fallback**: Primary 장애 시 Secondary 전환. 단 벤더마다 점수 산정 방식이 비공개라 점수 직접 비교 금지
- **휴먼 최종결정**: ML·룰 결과는 recommendation. 최종 판단은 분석가 — FATF 2021 para 276 "human/expert analysis"
- **증거 체인(Audit Trail)**: 모든 결정에 "입력·룰 ID·결정자·시각" 불변 기록
- **처리 기한은 회사 정책으로 명시**: 이전 판의 "1차 리뷰 4h / STR 48h"는 근거가 없어 삭제. 법정 기한이 있는 것만 법령에서 가져올 것(예: 2027-02-19부터 트래블룰 추가정보는 요청일부터 3영업일 이내)
- **개인정보 파이프라인 분리**: PII는 별도 보관소, 분석 파이프라인은 가명처리. 고유식별정보 처리 전산설비는 국내 소재(신고매뉴얼 2026-08-13, 클라우드 국내 리전 인정)([금융위 2026-08-13](https://www.fsc.go.kr/no010101/87521))

### 설계서에 반드시 포함해야 할 것

```
1. 도구 선정 근거 (PoC 비교 항목 — 가격·우열 평가가 아니라 측정 결과)
2. 룰 카탈로그: 각 룰의 근거 (FATF Red Flag 지표 ID 또는 규제 조문) 표기
3. 기록 보존: 업무규정 제80조(분석자료 5년 이상) / 이용자보호법 시행령 §13(상시감시·조치 기록 15년)
   / 통신사기피해환급법 §2의5④(임시조치 통지·해제·본인확인 내역)
4. AMLO 결재 경로 (RACI)
5. 예산·인력: 가정치임을 명시 (공개 벤치마크 없음)
6. 검사 대응 매뉴얼 — FIU / 금감원(§12) / 금융안전과(임시조치) 3분할
```

이전 판의 "연간 OpEx+CapEx 최소 5억~수십억"은 근거가 없어 삭제했습니다.

### 자주 나오는 오해

- **"설계서는 문서일 뿐"** — 검사에서는 문서와 실제 운영의 일치를 봅니다. 판단 근거가 케이스 기록에 남아야 업무규정 제79·80조의 분석·보존 요건을 충족합니다.
- **"MVP는 룰 몇 개면 충분"** — 이전 판의 "필수 8룰이 있어야 FIU 검사 통과"는 근거가 없어 삭제했습니다. 법령은 룰 개수를 정하지 않습니다. 룰 셋은 회사 위험평가로 정하고 FATF 2021 para 278에 따라 정기 재검토합니다. 출발점으로는 FATF Red Flag(2020) 6범주 58개 지표와 7차 TU 권고 5·6(지갑 스크리닝·블랙리스트·동결, 급속 이전·브리지·믹서·크로스체인 노출)이 있습니다.
- **"2027년부터 1천만원 이상은 자동 STR 룰"** — 아닙니다. 고시 §28-2③은 해외 VASP·자기수탁 이전에 대한 "자체 의심거래 감시체계 구축·운영"입니다(enacted-not-in-force).
