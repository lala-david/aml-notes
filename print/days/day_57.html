Blockchain Analytics — 온체인 분석 기법

KYT의 **기술적 기반**. 어떻게 익명 주소를 분석하는가. 이 글을 읽고 나면 블록체인 분석 도구가 어떤 휴리스틱과 데이터 위에서 돌아가는지, 그리고 그 결과의 정확도에 대해 **공개적으로 말할 수 있는 것과 없는 것**이 무엇인지 구분할 수 있습니다..

정정 안내 (2026-10-21). 이 노트의 이전 판에는 CIOH·CoinJoin 필터·GNN의 Precision/Recall/F1 비교표가 세 군데(§2.A, §2.B, §11.2) 있었습니다. 표에 출처로 단 Meiklejohn 2013·Möser & Böhme 2017·Androulaki 2013·Bellei 2024 어느 논문도 그 수치를 보고하지 않습니다. kb/facts/contradictions.jsonl CTR:00007(2026-08-04)이 같은 계열 수치를 다른 두 파일에서 지웠고, 이 파일에 남아 있던 세 표도 이번에 지웠습니다. Weber 2019·Elliptic++·Elliptic2의 수치와 브리지 정확도 표, Monero 서술도 원문에 맞게 고쳤습니다. 근거는 research/2026-10-academic-literature.md §8과 정본 보고서 부록 A-38·A-39입니다.

TL;DR

  • 블록체인 분석의 두 축: Clustering(주소 묶기) + Attribution(주소→엔티티 매핑). 그 위에 노출도(exposure) 산정이 올라간다.
  • 핵심 휴리스틱: Common Input Ownership(CIOH), Change Detection, Deposit Heuristic. 이 휴리스틱들의 표준화된 정확도 수치는 존재하지 않는다. Möser & Narayanan은 초록에서 "current techniques rely on heuristics that have not been rigorously evaluated or optimized"라고 썼다(arXiv 2107.05749).
  • Bitcoin(UTXO 모델)과 Ethereum(Account 모델)은 분석법이 다르다.
  • 크로스체인 추적은 2025년에 "휴리스틱"에서 "자동 매칭 시스템"으로 넘어갔다. 다만 연구마다 브리지 집합·정의가 달라 수치를 서로 비교할 수 없다.
  • 프라이버시 프로토콜은 "추적 불가/가능" 이분법이 아니라 익명성 집합 축소율·비트 손실로 측정된다. Monero도 2019~2023년 지갑 버그 구간은 부분 추적이 가능했다.
  • 한계: 새 mixer·브리지의 라벨링 지연, off-chain(CEX 내부) 거래, 공개 벤치마크와 실운영 사이의 격차.

1. 두 축 — Clustering + Attribution, 그리고 노출도

블록체인 분석이 답하려는 두 질문

  1. 이 주소들이 같은 사람인가? → Clustering
  2. 이 클러스터는 누구인가? → Attribution

이 둘이 합쳐져야 "주소 0x...가 누구"를 말할 수 있습니다. Clustering은 알고리즘에 가깝고, Attribution은 데이터·OSINT·협력 관계에 의존합니다. 알고리즘은 논문으로 공개돼 있지만 라벨 데이터는 각 회사가 따로 쌓기 때문에, 분석 결과의 차이는 대부분 라벨에서 나옵니다.

마지막 단계의 출력은 "판정"이 아니라 사람이 검토할 알람입니다. FATF 2021 RBA 가이던스 para 276은 대량 거래에서는 자동화 시스템이 유일한 현실적 수단일 수 있지만 "flagged transactions should go through human/expert analysis"라고 요구합니다(FATF 2021 RBA 가이던스).

Clustering (구조 분석) + Attribution (라벨 데이터) → Exposure (노출도) → 사람 검토

2. 주요 클러스터링 휴리스틱

A. Common Input Ownership Heuristic (CIOH) — Bitcoin

한 트랜잭션의 여러 input 주소 = 같은 사람이 통제.

UTXO 모델 비트코인에서는 한 트랜잭션이 여러 UTXO를 input으로 소비합니다. 각 input을 소비하려면 해당 UTXO의 private key로 서명해야 하므로, 같은 트랜잭션에 모인 input들은 같은 개인키 소유자가 통제한다고 추정합니다.

왜 강력한가: 한 사용자가 주소를 여러 개로 쪼개도, 여러 UTXO를 합쳐 보내는 순간 그 주소들이 한 클러스터로 묶입니다.

예외·한계: CoinJoin(Wasabi, Samourai, JoinMarket) 같은 협력 소비는 서로 다른 엔티티가 의도적으로 input을 합치는 것이라 CIOH가 오작동합니다. 그래서 CIOH를 적용하기 전에 CoinJoin 형태의 트랜잭션을 먼저 걸러냅니다.

2.A Common Input Ownership Heuristic — 엄밀 정의

알고리즘:

def common_input_ownership(tx: Transaction) -> set[Address] | None:
    if len(tx.inputs) < 2:
        return None
    if is_coinjoin(tx):   # 2.B 참조
        return None
    return {inp.address for inp in tx.inputs}

전제: Bitcoin UTXO에서 여러 input을 한 tx에 소비하려면 각 input의 private key에 접근해야 함 → "소유자 동일"이라는 통계적 가정.

엄밀한 한계: - UTXO 모델에서만 성립. Ethereum Account 모델에는 적용 불가(from 주소가 항상 1개). - CoinJoin(의도적 input 합치기)은 가정 위반. - Custodial 거래소 hot wallet은 여러 고객 자금을 한 tx에 합침 → "거래소"라는 엔티티로는 맞지만 "고객"까지 맞지 않음.

정확도 — 표준화된 수치가 없다

이 자리에 있던 "실증 정확도" 표(Meiklejohn 2013·Weber 2019·Möser & Böhme 2017·Bellei 2024 출처)는 삭제했습니다. 표의 수치는 귀속된 논문에 없습니다(CTR:00007). 특히 Weber 2019와 Bellei 2024는 주소 클러스터링 논문이 아니라 거래·서브그래프 분류 논문입니다.

공개 문헌에서 확인되는 것은 다음 정도입니다.

  • Möser & Narayanan(FC 2022)은 기존 기법이 엄밀히 평가·최적화되지 않았다고 명시합니다(arXiv 2107.05749).
  • 같은 논문은 거스름 휴리스틱 26개 변종을 평가했고, 개별 휴리스틱의 진양성률은 "Most achieve true positive rates between 10-30%"였습니다. 랜덤포레스트 결합 모델은 FPR 0.1%에서 TPR 82%(임계값 투표 방식 37%)로 개선됐습니다(B, 본문 수치는 저장소 wave1 검증).
  • 같은 논문에서 제약 없는 거스름 병합은 Mt.Gox 클러스터를 2억 2,400만 주소(+1596%)로 부풀렸습니다. 클러스터 붕괴(cluster collapse)가 정확도 숫자보다 더 중요한 실무 위험입니다(B).

정확도는 데이터셋·시기·지갑 소프트웨어 구성에 따라 달라집니다. 벤더 PoC에서는 "정확도 몇 %"보다 ground truth를 무엇으로 잡았는지, 클러스터 붕괴를 어떻게 탐지하고 되돌리는지를 물어야 합니다(curriculum/day_30.md 참조).

2.B CoinJoin Fingerprint Detection (CIOH 전 필터)

문제: Wasabi·Samourai Whirlpool·JoinMarket 같은 CoinJoin은 서로 다른 사용자가 의도적으로 input을 합칩니다. CIOH 단독 적용 시 오분류가 납니다.

Fingerprint 탐지 규칙 (교육용 예시) — 특정 벤더의 구현이 아니며, 아래 상수는 이 노트가 검증하지 않은 자리표시자입니다.

def is_coinjoin(tx: Transaction) -> bool:
    # 1. Input 수 ≥ 2 (최소 조건)
    if len(tx.inputs) < 2:
        return False
    # 2. Output 동일 금액 클러스터 검출
    amounts = [o.value for o in tx.outputs]
    uniform_outputs = [a for a in amounts if amounts.count(a) >= 3]
    if not uniform_outputs:
        return False
    # 3. 지갑별 고정 denomination 대조
    #    값은 지갑·버전마다 다르다 — 각 지갑의 공개 문서로 확인한 뒤 채울 것
    KNOWN_DENOMS: set[int] = load_wallet_denominations()
    if any(a in KNOWN_DENOMS for a in uniform_outputs):
        return True
    # 4. Input/Output 수가 대칭인 구조
    if len(tx.inputs) >= 5 and len(tx.outputs) >= 5:
        if abs(len(tx.inputs) - len(tx.outputs)) <= 1:
            return True
    return False

결합 정확도: 이전 판의 "CIOH 단독 0.75 / Fingerprint 필터 후 0.95 / ML 분류기 0.97(벤더 추정)" 표는 출처가 없어 삭제했습니다. 공개 근거 없음.

참고: - Meiklejohn et al. (2013) "A Fistful of Bitcoins: Characterizing Payments Among Men with No Names" (ACM IMC 2013) - Möser & Böhme (2017) "Anonymous Alone? Measuring Bitcoin's Second-Generation Anonymization Techniques" (IEEE EuroS&PW 2017, DOI 10.1109/eurospw.2017.48) - Möser & Narayanan (2022) "Resurrecting Address Clustering in Bitcoin" (FC 2022, arXiv 2107.05749)

B. Change Detection (거스름돈 식별)

UTXO 모델에서 거스름돈(change)은 새 주소로 반환됩니다. 이 거스름돈 output을 원 주소 소유자와 같은 클러스터로 묶는 기법.

휴리스틱 예: - "optimal change": 입력이 2개 이상인 거래에서 어떤 출력이 모든 입력값보다 작으면 그 출력이 거스름일 가능성이 높다(Möser & Narayanan 정의, B) - 주소 타입 일치, 반올림 금액, 지갑 지문(트랜잭션 버전·locktime·RBF·스크립트 타입 등)

정확도: 이전 판의 "약 60~80%"는 출처가 없어 삭제했습니다. 위 논문 기준으로 개별 휴리스틱은 대체로 TPR 10~30% 수준이라 단독으로 쓰지 않고 결합합니다(B).

C. Deposit Heuristic (거래소 입금 식별)

배경: 거래소는 고객별로 입금 주소를 따로 발급합니다. 거래소는 입금된 자금을 주기적으로 consolidation 주소로 모아 핫월렛·콜드월렛을 관리합니다. 이 흐름을 따라가면 거래소 주소 체계가 드러납니다.

결과: 거래소 attribution의 핵심 방법. "이 주소에서 나가는 consolidation 흐름이 알려진 거래소 핫월렛으로 흐른다 → 이 주소는 그 거래소의 입금 주소" 식의 추론. 단, 입금주소 재사용·스윕 패턴 기반 식별의 정밀도를 공개 ground truth로 평가한 2025~2026 논문은 확인되지 않았습니다(academic §3-6).

D. Behavior-based Clustering (행동 기반)

  • 시간대, 금액, 거래 빈도 패턴이 비슷한 주소들
  • ML 기반
  • 약한 신호지만 다른 휴리스틱과 결합 시 유용

E. Multi-input Heuristic for Ethereum (계정 모델)

Ethereum은 UTXO가 아닌 Account 모델이라 CIOH를 직접 적용할 수 없습니다. 대신 다음 패턴을 활용합니다.

  • 같은 EOA(Externally Owned Account)가 여러 contract와 상호작용하는 패턴
  • Smart contract 호출 패턴 (funding relationship)
  • Gas 지불 주소 분석 (누가 ETH로 가스비를 내는가)
  • 같은 ENS 도메인 사용

2025년 연구는 계정 모델에서 방향·시간 피처와 거래 텍스트화로 이 공백을 메우려 합니다. DiT-SGCR은 방향성 시간 집계와 미분가능 클러스터링을 결합한 비지도 인코더로, 3개 데이터셋에서 기존 SOTA 대비 F1 3.62~10.83%p 향상을 보고했습니다(arXiv 2506.20123). KGBERT4Eth는 거래 언어모델과 지식그래프를 결합해 피싱 탐지 F1 8~16%p, 비익명화 6~26%p 개선을 보고했습니다(arXiv 2509.03860). 두 편 모두 동료심사 전 프리프린트이고 개선폭만 보고합니다.

용어: - EOA (Externally Owned Account) — 사용자가 private key로 통제하는 Ethereum 계정. - UTXO (Unspent Transaction Output) — Bitcoin의 미사용 거래 출력. 비트코인의 기본 단위.

실무 포인트

Ethereum은 Bitcoin보다 클러스터링이 구조적으로 더 어렵습니다. CIOH 같은 강한 구조 신호가 없기 때문입니다. 그래서 Ethereum 쪽 결과는 라벨 데이터(Attribution)에 더 크게 의존한다고 기억하면 됩니다. 체인별 정확도를 수치로 비교한 공개 벤치마크는 없습니다.

3. Attribution — 주소를 누구에게 매핑하나

데이터 소스

Attribution은 "알고리즘"이 아니라 "데이터 누적"의 문제입니다.

소스 예시

다크넷 마켓 운영 관찰로 주소 라벨링
법집행 정보 압수·체포로 노출된 주소
제재 목록 OFAC SDN 등 정부 발표 주소
Smart Contract 분석 컨트랙트 deployer, 함수 호출 패턴
소셜 / OSINT 소셜미디어·메신저에서 주소 노출

라벨 카테고리 (일반적 예시)

  • Exchange · DEX · Mixer · Sanctions · Stolen Funds · Ransomware · Darknet Market · Scam · Gambling · Mining Pool · High-risk Jurisdiction Exchange · ATM · Merchant Service

실무 포인트

라벨 데이터의 한계는 감독기관 문서에도 적혀 있습니다.

  • FATF 2021 RBA 가이던스 para 234: "There is a cost consideration with these tools and not all VAs are covered by all vendors." 프라이버시·데이터보호 영향도 고려하라고 합니다(FATF 2021).
  • NYDFS 산업서한(2022-04-28)은 지원하는 자산마다 추적 절차를 갖추라고 요구하고, 외부 서비스와 자체 개발 도구를 모두 허용합니다. 분석 도구가 "may not be able to identify underlying owners"라는 한계도 명시합니다(NYDFS).
  • FATF 7차 Targeted Update(2026-07-16)는 MIVA 표 검증에 "blockchain analytics companies' data"를 썼다고 밝히면서도, 그 데이터가 관할의 불법금융 위험 평가에 기반한 것은 아니라고 단서를 답니다(FATF 7차 TU).

벤더별 지역·분야 강점을 비교한 공개 평가는 확인되지 않았습니다. 커버리지는 PoC에서 자사 지원 자산 목록을 기준으로 직접 확인해야 합니다.

4. Exposure Score — 개념과 공개 근거의 한계

4.1 정의

노출도(Exposure): 한 주소(또는 클러스터)가 위험 엔티티(제재 대상·믹서·다크넷 등)와 어떻게 연결돼 있는지를 정량화한 값.

  • Direct: 분석 대상이 위험 엔티티와 직접 거래
  • Indirect: 중개 주소를 거쳐 도달

간접 노출을 보는 규범적 근거는 FATF 2021 RBA 가이던스 para 277입니다. 고위험 상황의 강화 모니터링은 "extend beyond the immediate transaction between the VASP or its customer or counterparty"여야 하고, 기준·임계값은 "reviewed on a regular basis"여야 합니다(FATF 2021). FATF 7차 TU는 VASP가 "transactions monitoring and blockchain analytics tools"로 급속 이전을 탐지하고, 프로토콜·브리지·믹서·크로스체인 도구에 대한 노출을 평가하라고 권고했습니다(FATF 7차 TU).

4.2 공식에 대해 말할 수 있는 것

이전 판에는 "벤더 일반화 공식", 카테고리별 가중치 표, 벤더별 감쇠계수 λ 표, "보통 5-hop까지"라는 서술과 그 계산 예시가 있었습니다. 모두 공개 근거가 없어 삭제했습니다(정본 보고서 부록 A-37, kyt 도시에 §9 #8).

2026-10-21 기준 이 저장소의 조사에서 홉 수 상한·감쇠함수·카테고리 가중치를 공개한 벤더 자료는 확인되지 않았습니다. 따라서 노출도 점수는 재현할 수 없는 블랙박스로 다뤄야 합니다. 구조만 적으면 다음과 같습니다. 계수는 일부러 비워 둡니다.

4.3 점수 다음 단계 — 자동 STR이 아니다

이전 판의 계산 예시는 "64점 → BLOCK + STR 자동 발동"으로 끝났습니다. 이것은 틀린 연결입니다. 노출도 점수는 차단·통보·STR 판단의 입력일 뿐입니다. 한국 「자금세탁방지 및 공중협박자금조달금지에 관한 업무규정」은 제76조~제81조에서 거래모니터링체계와 보고체제를 규정하고(법제처), FATF는 플래그된 거래의 사람 검토를 요구합니다. 산출물을 차단/통보/STR 세 축으로 나누는 설계는 kyc-kyt.md를 보세요.

4.4 한계

  1. 노출도는 과거 라벨 기반 → 새 라벨이 반영되기까지 지연이 있습니다(지연 기간을 측정한 공개 자료는 확인되지 않음).
  2. 간접 노출을 깊이 따라갈수록 무관한 주소가 섞입니다. 깊이를 어디서 끊는지가 공개돼 있지 않다는 점이 설명 가능성의 문제입니다.
  3. 프라이버시 프로토콜 진화 → Railgun 같은 shielded pool은 §7.5의 측정 연구를 보세요.
  4. Cross-chain → 브리지 매칭이 따로 필요합니다(§5).

실무 포인트

노출도 공식은 벤더마다 다르고 공개되지 않습니다. 이게 STR 작성 시 "왜 이 점수인가"를 설명하기 어려운 원인입니다. 대응은 벤더에게 카테고리별 하위 점수와 추적 경로를 받아 사내 정책 언어로 다시 쓰는 것입니다. FATF 2021 para 276이 "operating rules"를 이해하고 무결성을 정기 검증하라고 요구한다는 점을 근거로 들 수 있습니다.

5. Cross-chain Tracing — Bridge Matching

도전

한 체인에서 끊어진 흐름이 다른 체인에서 시작되는 구조. 중간에 wrapped 토큰화(A 체인의 ETH가 B 체인의 wETH로)로 같은 가치지만 다른 형태가 됩니다.

5.1 문제 정의

Ethereum → Polygon → Arbitrum → Optimism 간 자산 이동은 bridge contract를 거칩니다. 각 체인의 tx는 독립적이므로, 추적을 이어 가려면 "bridge event를 체인 간 연결"해야 합니다. 2025년 연구(ConneX)는 브리지 양측 거래 쌍 매칭 실패가 자금 추적 실패의 주원인이라고 문제를 정의했습니다(arXiv 2511.01393).

5.3 매칭 알고리즘 (교육용 예시)

time_window·amount_tolerance 기본값은 예시입니다. 실측 연구(§5.5)에서는 입금과 출금의 시간창이 크게 달랐습니다.

def match_bridge_events(
    lock_events: list[LockEvent],
    mint_events: list[MintEvent],
    time_window: int,          # 초 — 브리지·방향별로 따로 정한다
    amount_tolerance: float,   # 수수료 차감 토큰은 별도 처리
) -> list[tuple[LockEvent, MintEvent]]:
    matches = []
    for lock in lock_events:
        candidates = []
        for mint in mint_events:
            if mint.token_canonical != lock.token_canonical:
                continue
            if abs(mint.timestamp - lock.timestamp) > time_window:
                continue
            if abs(mint.amount - lock.amount) / lock.amount > amount_tolerance:
                continue
            # 순번(nonce) 필드가 양쪽에 있으면 결정적 매칭
            if hasattr(lock, 'nonce') and hasattr(mint, 'nonce'):
                if lock.nonce == mint.nonce:
                    candidates = [mint]
                    break
            candidates.append(mint)
        if len(candidates) == 1:
            matches.append((lock, candidates[0]))
        elif len(candidates) > 1:
            # 금액 차이 최소 선택 (차선책 — 오매칭 위험 기록)
            best = min(candidates, key=lambda m: abs(m.amount - lock.amount))
            matches.append((lock, best))
        # 0개: 목적지 체인에 아직 도착 안 함 — 재큐잉
    return matches

5.6 한계

  • 여러 브리지를 연달아 거치면 단계마다 오류가 누적됩니다. 이전 판의 "3-hop ≈ 0.73" 계산은 출처 없는 단일 브리지 수치를 곱한 것이라 삭제했습니다.
  • 비표준 경로(중앙화 OTC·P2P)는 온체인 브리지 이벤트가 없습니다.
  • THORChain·Across 같은 유동성 풀 기반 브리지는 sender-receiver가 1:1로 연결되지 않습니다.
  • DeFi 거래의 의미 해석이 병목입니다. AMLGuard는 DeFi 거래를 "DeFi Semantic Unit"으로 추상화해, 실제 세탁 사건 82건에서 목적지 정밀도 94.4%(단일체인)/87.6%(크로스체인)를 보고했습니다(arXiv 2607.18869). 알려진 사건만 쓴 평가라 선택 편향이 있습니다.

실무 포인트

FATF 7차 TU가 브리지·크로스체인 도구 노출 평가를 명시했으므로, 크로스체인 추적은 선택 기능이 아니라 위험평가 항목입니다. PoC에서는 자사가 지원하는 체인 조합으로 실제 경로를 여러 개 만들어 복원 여부를 직접 확인하고, 결과를 브리지·방향·자산 유형별로 기록하세요. 단일 정확도 숫자로 요약하지 않는 것이 핵심입니다.

7. 분석 도구의 데이터 파이프라인

  1. Node Operation — Bitcoin Core, Geth, Erigon, Reth 등. 전체 이력이 필요하면 archive node.
  2. Indexing — 트랜잭션을 그래프 저장소에 적재, 주소 ↔ 트랜잭션 매핑.
  3. Heuristic Clustering — CIOH·Change Detection·Deposit 휴리스틱으로 클러스터 ID 부여. 병합 제약과 붕괴 점검을 둡니다(Möser & Narayanan의 지출-출력 제약 사례, B).
  4. Attribution — 라벨 DB(자체 + 외부)로 클러스터 → 엔티티 매핑.
  5. Risk Scoring — 노출도 계산.
  6. API / UI — 외부 API, 분석가용 시각화. 출력은 사람 검토로 갑니다.

실무 포인트

8. ML·AI의 활용

적용 영역

  • 클러스터링 보조: 휴리스틱이 잡지 못하는 패턴 발견
  • 거래·서브그래프 분류: Elliptic(거래 노드), Elliptic2(서브그래프)
  • 믹서 계정 연결: §7.5
  • 피싱·rug pull 탐지: PhishEye는 자기지도 방식으로 실배포에서 미지의 피싱 주소 1,803개를 찾았습니다(arXiv 2605.01207). RugScreener는 균형 데이터(500/500)에서 균형 정확도 95.7%를 보고했습니다(IEEE TIFS 2025).

공개 벤치마크가 실제로 말하는 것

  • Weber et al. 2019(Elliptic 공개 논문)에서 최고 성능은 GNN이 아니라 랜덤포레스트였습니다. 불법 클래스 기준 RF(전체 피처+노드 임베딩) precision 0.971 / recall 0.675 / F1 0.796, GCN 0.812 / 0.512 / 0.628(arXiv 1908.02591, 본문 수치 B). 이전 판의 "RF 0.93/0.77/0.84, GCN 0.92/0.83/0.87"은 논문과 다릅니다.
  • 같은 논문에서 시점 43의 다크마켓 폐쇄 이후 모든 모델의 성능이 급락했습니다(B). 개념 표류(concept drift)가 운영 위험의 본질입니다.
  • Elliptic2의 GLASS 모델은 F1 0.933이지만 PR-AUC 0.208, 혼동행렬 TP 245 / FP 765 — 의심으로 예측한 4건 중 약 1건만 실제 의심입니다(B)(arXiv 2404.19109). 극단적 불균형에서 F1만 보면 오독합니다.
  • Elliptic 시계열 분할에서 Extra Trees AUPRC 0.570 vs GraphSAGE 0.311로 트리 앙상블이 앞섰습니다(B)(Akter 외 2026).
  • GCN·GAT·GraphSAGE의 Elliptic 결과는 가중치 초기화·정규화 선택만으로 달라집니다(arXiv 2602.23599). 논문 간 F1 비교표를 만드는 것 자체가 위험합니다.
  • TransXion(KDD '26)은 템플릿 기반 이상 주입 벤치마크가 모델 강건성을 과대평가한다고 보였습니다(arXiv 2604.17420).

한계

  • 라벨 데이터 부족 — 각 회사가 자체 보유하고 공개하지 않습니다. Elliptic·Elliptic2 이후 자금세탁 라벨 Bitcoin/Ethereum 데이터셋의 신규 공개는 2026-10-21 기준 확인되지 않았습니다(academic §3-11).
  • Adversarial behavior — 분석을 회피하는 패턴(분할 금액, 무작위 시간). 경제적 동기를 가진 공격자를 모델링한 연구는 사실상 공백입니다.
  • 모델 설명가능성 — 규제 보고 시 "왜 STR 보고했나"를 설명해야 합니다. 근거 인용을 강제한 LLM 트리아지 연구는 인용 유효성 0.98인데 에스컬레이션 F1은 0.62였습니다(합성 데이터)(arXiv 2604.19755). 근거를 잘 인용한다고 판단이 맞는 것은 아닙니다.

실무 포인트

ML 탐지는 보조 수단으로 쓰는 게 안전합니다. 감독 검사에서 "이 고객은 어떤 근거로 STR 대상이 됐나"에 "모델이 그렇게 판단했다"는 답이 될 수 없습니다. 공개 근거로 보면 그래프 모델의 실무 우위는 확인되지 않았고, 트리 앙상블과 운영 지표(PR-AUC, 혼동행렬 원값)로 먼저 검증하라는 것이 2026년 문헌의 공통 메시지입니다.

9. 자체 구축 vs 벤더 활용

규제가 허용하는 것

  • NYDFS(2022-04-28): 외부 서비스와 자체 개발 도구 모두 허용, 다만 자산별 추적 절차와 역할 분담을 문서화하라고 요구(NYDFS).
  • FATF 2021 para 156(c)는 EDD 수단으로 블록체인 분석을 들고, para 323(g)는 일본 JFSA가 "whether blockchain analysis tools are used for transaction monitoring and/or risk analysis purposes"를 감독 KPI로 수집한다고 적었습니다(FATF 2021).

판단 기준

  • 벤더: 라벨 DB·다체인 커버리지를 바로 얻습니다. 대신 노출도 공식이 비공개라 설명 책임이 남습니다.
  • 자체 구축: 사내 데이터와 결합하고 국내 특화 라벨을 쌓을 수 있습니다. 대신 노드·인덱싱·라벨링을 직접 감당합니다.
  • 대부분은 외부 분석 도구 + 자체 보완 모듈의 조합입니다. 특정 거래소가 어느 벤더를 쓰는지는 공개 확인된 범위가 좁으므로 일괄 서술하지 않습니다.

실무 포인트

"자체 구축 vs 벤더"의 답은 비용보다 규제 대응 근거로 봐야 합니다. 어느 쪽이든 감독기관 앞에서 필요한 것은 같습니다. 지원 자산별 추적 절차, 룰·임계값의 정기 검토 기록, 플래그 거래의 사람 검토 기록입니다.

10. 한계와 미래

한계

  • Privacy coin(Monero): 2023년 패치 이후 거래에는 알려진 버그 기반 휴리스틱이 통하지 않습니다(§7.5). 패치 이전 구간은 부분 추적이 가능했습니다.
  • 새 mixer·새 bridge: 라벨링 지연. 지연 기간을 측정한 공개 자료는 확인되지 않았습니다.
  • Off-chain(CEX 내부 거래): 보이지 않습니다.
  • 관할 귀속: 가명 주소에는 지리 식별자가 없어 단일 관할 내 온체인 활동을 측정하기 어렵습니다. ECB CAMEG는 2026년 계획에 지리적 위치 식별 방법론·지표 개발을 넣었습니다(ECB OP 382).

미래 방향

  • 서브그래프·경로·의도 추적: 거래 하나가 아니라 자금 흐름 전체를 탐지 단위로 삼는 쪽(§12).
  • Cross-chain analytics 표준화: 공통 벤치마크가 아직 없습니다.
  • ZKP 적용 — 프라이버시와 컴플라이언스 양립. SSI·ZKP·속성기반 접근제어로 KYC 준수 dApp의 온체인 권한부여를 구현한 연구(arXiv 2510.05807), 중앙은행 전문가의 PET 분류(BIS Innovation Hub Mandala 예시, ECB OP 382 §2.10.2)가 있습니다.

실무 포인트

ZKP 기반 프라이버시-컴플라이언스 양립은 장기 방향입니다. 2026-10-21 기준 학술 문헌은 설계·분류 단계이고, 감독 실무에서 채택된 사례를 다룬 평가 논문은 확인되지 않았습니다.

요약 부록 — 빠른 참조용

두 축: Clustering (구조) + Attribution (데이터) → 노출도 5대 휴리스틱: CIOH · Change · Deposit · Behavior · Ethereum Multi-input 정확도: 표준화된 수치 없음. 클러스터 붕괴 점검이 더 중요 체인별 차이: Bitcoin UTXO = 구조 신호 있음 / Ethereum Account = 라벨 의존 노출도: Direct / Indirect. 홉 상한·가중치·감쇠는 비공개 → 블랙박스로 취급

💼 실무 현장 (Industry Reality)

이전 판의 벤더 매출 비중·조달액·인력 규모·노드 비용·"KYT 벤더별 강점 PoC 비교"·국내 거래소별 사용 벤더·"자체 구축 실패" 사례는 모두 공개 출처가 없어 삭제했습니다.

감독기관이 블록체인 분석에 대해 실제로 쓴 문장

  • FATF 7차 TU(2026-07-16) 민간부문 권고: "identify suspicious patterns in VA transactions and detect rapid transfer of VAs using transactions monitoring and blockchain analytics tools." FATF 공식 문서가 VASP 대상 권고에 "blockchain analytics tools"를 직접 쓴 것은 이 조사 범위에서 처음입니다.
  • 같은 문서는 통제 요소로 "KYC, wallet screening, blacklisting, and, where appropriate, whitelisting mechanisms as well as freezing and blocking capabilities"를 열거합니다.
  • 업계 용어 "KYT"는 FATF 7차 TU·2021 RBA 가이던스·2020 레드플래그·MAS PSN02 어디에도 나오지 않습니다. 한국 업무규정의 용어는 "거래모니터링체계"(제76조)입니다.

자주 나오는 오해

  • "CIOH 정확도는 몇 %다" — 표준화된 수치는 없습니다. 숫자를 들었다면 데이터셋·시기·ground truth를 되물으세요.
  • "GNN이 최신이니 더 정확하다" — Elliptic 원논문에서도, 2026년 재평가에서도 트리 앙상블이 앞섰습니다(§8).
  • "Monero는 완전히 추적 불가"/"Monero도 다 추적된다" — 둘 다 틀렸습니다. 시기를 나눠야 합니다(§7.5).
  • "제재하면 믹서는 끝난다" — Tornado Cash 입금은 71.03% 줄었지만 보안사고의 78.33%가 여전히 경유했습니다. "효과 있음/없음" 이분법이 맞지 않습니다.
  • "발행자가 동결하면 자금은 묶인다" — USDT 7.3%, USDC 18.7%의 제재 주소가 동결 전에 전액 인출했습니다. BIS도 발행자 동결·분석업체 지원이 "cannot replace routine, large-scale AML/CFT controls in everyday payments"라고 했습니다(BIS AER 2026).

12. 연구 흐름 2019 → 2026

2025~2026년의 이동을 정본 보고서는 다섯 가지로 요약합니다. (1) 노드 분류 → 서브그래프·경로·의도 추적, (2) 크로스체인 자동 매칭, (3) 프라이버시 프로토콜의 정량 측정, (4) 사기 측정 규모 확대(address poisoning 2.7억 건, arXiv 2501.16681), (5) 벤치마크 회의론. 반대로 트래블룰 효과 실증, LLM의 실데이터 평가, 자기수탁 지갑 소유 검증을 다룬 2025~2026 동료심사 논문은 확인되지 않았습니다. 논문 목록은 ../../deep/papers.md의 2025~2026 섹션을 보세요.

KYC / KYT — 가상자산 AML 기술의 두 축

KYC(사람을 안다) + KYT(거래·지갑을 안다). 이 글을 읽고 나면 두 시스템이 왜 **공통 데이터·케이스 관리를 공유하되 법적 산출물은 따로 내보내야 하는지**, 그리고 "KYT"라는 말이 규제 문서에서 어떻게 불리는지 판단할 수 있게 됩니다..

TL;DR

  • KYC: 사람·법인의 신원확인 (공통)
  • KYT: 거래·지갑주소의 위험 분석. 단, "KYT"는 규제 용어가 아니다 — FATF 7차 Targeted Update·2021 RBA 가이던스·2020 Red Flag·MAS PSN02 어디에도 "KYT"는 0회 나오고, 감독기관의 언어는 "transaction(s) monitoring", "blockchain analytics (tools)", "wallet screening", "ongoing monitoring"이다. 한국 「자금세탁방지 업무규정」은 "거래모니터링체계"(제76~81조) 라고 쓴다.
  • FATF는 2026-07-16 7차 TU에서 처음으로 VASP에 "transactions monitoring and blockchain analytics tools"로 급속 이전(rapid transfer)을 탐지하라고 권고했다.
  • 한국에서 "이상" 신호는 세 개의 법적 출구로 갈라진다: ① FDS·보이스피싱 임시조치(통신사기피해환급법, 거래소 적용 2026-10-01~) ② 시장감시 통보(가상자산이용자보호법 §12) ③ 의심거래보고 STR(특금법 §4). Risk Engine 출력을 한 축(ALLOW/EDD/STR/BLOCK)으로 그리면 틀린다.
  • 노출도(exposure) 산정 깊이·감쇠·가중치를 독립 검증 가능한 형태로 공개한 벤더는 없다. 이 저장소의 노출도 공식은 가설 모델이다.

1. KYC 프로세스 — 5단계 파이프라인

왜 파이프라인 구조인가

KYC는 "신분증 한 번 찍고 끝"이 아니라 onboarding → verification → screening → assessment → ongoing monitoring로 이어지는 연속 공정입니다. 각 단계가 막히면 이후 단계 전체가 실패하므로, 실무에서는 단계마다 실패 지점과 fallback을 명확히 설계해야 합니다.

파이프라인 구조

1. Onboarding (가입)
   ├─ 개인정보 수집 (이름·생년월일·주소·연락처)
   ├─ 신분증 OCR + 진위확인
   ├─ Liveness check (얼굴 영상 + 신분증 사진 매칭)
   └─ 휴대폰·이메일 인증

2. Verification (검증)
   ├─ 본인인증 (한국: 본인확인기관)
   ├─ 주소 증빙
   └─ 직업·소득 (선택, EDD 시 필수)

3. Screening (스크리닝)
   ├─ PEP 데이터베이스 매칭
   ├─ Sanctions list (OFAC·UN·EU·한국)
   ├─ Adverse media (부정적 보도)
   └─ 가상자산 지갑주소 제재목록

4. Risk Assessment (위험평가)
   ├─ 국가 위험 (FATF 고위험·회색명단)
   ├─ 직업 위험
   ├─ 거래 의도 (예상 금액·빈도·상대국)
   └─ 종합 risk score → 등급

5. Ongoing Monitoring (지속 모니터링)
   ├─ 거래 패턴 vs 신고 의도 비교
   ├─ 위험요소 변경 시 재실사
   └─ EDD 트리거 발동 시 추가 절차

용어: - OCR (Optical Character Recognition) — 이미지에서 텍스트를 자동 추출. - Liveness Check — 실제 살아있는 사람인지 검증. 사진·영상·마스크 스푸핑 방어. - Adverse Media — 부정적 뉴스·소송·제재. PEP·Sanctions를 넘어서는 평판 리스크 확인.

실무 포인트

5단계 중 가장 자주 실패하는 건 5번 Ongoing Monitoring입니다. FATF 2021 가이던스 para 275~276은 지속 모니터링을 "고객정보·거래목적 대비 거래 일관성 검증"으로 정의합니다(FATF 2021 RBA 가이던스). 재실사 주기는 법령이 일률로 정하지 않으므로 회사 위험평가로 정하고 근거를 남겨야 합니다.

2. KYC 기술 컴포넌트

이 표를 어떻게 읽어야 하나

각 컴포넌트는 대체 가능한 벤더가 여러 개 있습니다. 선정 시 고려할 축은 (1) 한국 신분증 포맷 지원, (2) Liveness 스푸핑 방어 수준, (3) 국외 PEP DB 커버리지, (4) SDK 연동 용이성. 이전 판의 "벤더 예시" 열은 국내 채택을 뒷받침하는 공개 1차 근거가 없어 삭제했습니다.

컴포넌트 기술
OCR 신분증 텍스트 추출
Document Authentication 위변조 검증 (홀로그램·MRZ·배경)
Liveness Check 실제 사람 vs 사진·영상
Face Matching 신분증 사진 vs 실시간 셀카
PEP / Sanctions DB 글로벌 watchlist 매칭
Adverse Media 뉴스·제재·소송 검색
Korean ID Verification 본인확인기관 연동
Risk Scoring RBA 점수 계산

실무 포인트

한국 특화의 핵심은 본인확인기관 연동입니다. 글로벌 KYC 도구가 신분증 OCR·얼굴 매칭을 해도 본인확인기관 연동을 대신하지는 못하므로, 실무 구성은 "글로벌 도구 + 국내 본인확인" 조합이 됩니다.

3. KYT(거래모니터링) 프로세스 — 입금 스크리닝에서 STR까지

규범상의 뼈대

KYT의 규범적 근거는 벤더 문서가 아니라 다음 문서들입니다.

문서 핵심 요구 출처
FATF 2021 RBA 가이던스 para 273 고객·상대방 지갑주소를 블랙리스트 주소와 대조 FATF 2021
같은 문서 para 275~276 "automated systems may be the only realistic method of monitoring transactions, and flagged transactions should go through human/expert analysis", 운영 룰 무결성 "regular basis" 검증 같음
같은 문서 para 277~278 고위험 상황에서 모니터링을 "extend beyond the immediate transaction"(간접 노출 추적의 근거), 임계값 정기 재검토 같음
같은 문서 para 234 분석도구의 비용·벤더별 자산 커버리지 한계, 프라이버시 영향 고려 같음
NYDFS 산업서한 (2022-04-28) 지원 자산별 추적 절차, 외주·자체 도구 모두 허용, 분석도구가 "may not be able to identify underlying owners" NYDFS
MAS PSN02 (2025-06-30 개정, 2025-07-01 시행) ¶6.27 FATF 기준 감독을 받지 않는 상대와 DPT 이전 시 강화조치 MAS PSN02
FATF 7차 TU (2026-07-16) 민간 권고 5-ii·6 "KYC, wallet screening, blacklisting, and, where appropriate, whitelisting mechanisms as well as freezing and blocking capabilities"; "detect rapid transfer of VAs using transactions monitoring and blockchain analytics tools"; 브리지·믹서·크로스체인 노출 평가 7차 TU PDF
한국 「자금세탁방지 업무규정」(FIU 고시 제2025-2호, 2025-10-22 발령·2026-01-22 시행) 제76~81조 거래모니터링체계 범위(76), 비정상 거래 주의(77), 고객정보·거래이력·과거사례 비교와 위험도 측정·패턴 분석 절차(78), 분석담당자·FIU 보고·정보화(79), 분석자료 5년 이상 보존(80), 보고체제(81). 본문에 "가상자산"은 0회 법제처 DRF

한국 KYT의 법적 근거는 가상자산 전용 조문이 아니라 금융권 공통 규정이라는 점이 중요합니다. 2027-02-19부터는 특금법 시행령 §10-20 ⑦나와 FIU 고시 제2026-2호 §28-2③에 따라 해외 VASP·자기수탁 지갑과의 1천만원 이상 이전에 대해 "자체 의심거래 감시체계"를 구축·운영해야 합니다(enacted-not-in-force). 이것은 "자동 STR"이 아닙니다. 입법예고안(2026-03-30)의 "위험도와 관계없이 의심거래로 보고"는 공포본(대통령령 제36592호, 2026-08-18 공포)에서 감시체계 의무로 바뀌었습니다(감독규정 FIU 고시 제2026-2호; 금융위 2026-08-11). 고시 §28-2의 정확한 시행일(2027-02-19 또는 02-21)은 기산점이 확정되지 않았습니다.

처리 흐름

단계별 설명

1. Address Discovery (주소 등록)
   ├─ 입금 주소 = 자체 발급 → 자동 매핑
   ├─ 출금 주소 = 사용자 입력 → 외부지갑 등록
   └─ 트래블룰 상대 VASP 주소

2. Address Attribution (행위자 매핑)
   ├─ 분석 벤더 라벨 조회
   ├─ 자체 클러스터링 결과
   └─ 상대 VASP 식별 (주소만으로 완전한 식별은 불가 — FATF 2021 para 197(a))

3. Exposure Analysis (노출 분석)
   ├─ Direct exposure: 상대 주소가 곧 위험 엔티티
   ├─ Indirect exposure: 중간 경유 후 위험 엔티티 도달
   └─ Source(입금) vs Destination(출금) 분리

4. 패턴 탐지
   ├─ 온체인 신호: peel chain, 믹서·브리지 경유, 급속 분산
   └─ 오프체인 행위 신호: 분할 입출금, 입금 직후 출금(pass-through), 접속 이상
      → 오프체인 행위 신호는 FDS(사기)와 AML(세탁) 양쪽이 쓰는 신호다

5. Decision (의사결정)
   ├─ 알람 → 사람 검토
   ├─ 케이스 → STR / EDD·거래거절 / 종결
   └─ 사기 피해 의심이면 FDS 임시조치 절차로 넘김 (§6)

실무 포인트

외부 분석 API 호출이 가장 느린 단계입니다. 자주 조회되는 주소는 캐싱하고 캐시 miss 시 비동기 조회로 넘기는 설계를 고려하되, 벤더 장애 시에도 "판단 보류"가 기록으로 남게 해야 합니다. 응답 시간·가용성에 관한 벤더 수치는 모두 자사 주장(T5)이라 이 저장소는 싣지 않습니다.

4. KYT 핵심 개념

Cluster (클러스터)

정의: 같은 사람·엔티티가 통제하는 주소 집합.

  • 휴리스틱 + 머신러닝 + 라벨링으로 구성
  • 한 거래소가 많은 입금 주소를 운영해도 분석 도구에서는 한 클러스터로 묶일 수 있음
  • UTXO 모델(Bitcoin)은 공동입력 휴리스틱이 있어 클러스터링이 상대적으로 쉽고, Account 모델(Ethereum)은 다른 휴리스틱이 필요

Attribution (귀속)

정의: 클러스터를 알려진 엔티티에 매핑.

  • 라벨 DB가 분석 벤더의 핵심 자산이다. 다만 라벨 정확도에 대한 공개 벤치마크는 없다.
  • 이전 판의 "누적 추적 거래량 $24T+, 매핑 주소 10억+"는 출처가 없어 삭제했다. 벤더 홈페이지의 라벨 주소 수·고객 수는 자사 주장(T5)이다.
  • 귀속의 한계는 감독기관도 인정한다: NYDFS는 분석도구가 실소유자를 "may not be able to identify"라고 적었다.

Exposure (노출도)

정의: 한 주소가 위험 주소와 어떤 관계에 있는가를 정량화한 것.

  • Direct: 위험 엔티티와 바로 거래
  • Indirect: 중간 주소를 거쳐 도달
  • 규범적 근거는 FATF 2021 para 277~278의 "extend beyond the immediate transaction"이다.

공개 근거의 범위: kyt 도시에가 확인한 바로는 홉 수 상한·감쇠계수·카테고리 가중치를 독립 검증 가능한 형태로 공개한 벤더는 없다. 한 벤더는 제품 페이지에서 간접 노출을 "식별된 서비스에 도달할 때까지 필요한 만큼의 홉"으로 추적한다고 적지만 이는 자사 서술(T5)이다. 따라서 저장소에 있던 다음 서술은 가설 모델로 격하한다.

이전 서술 처리
score = clip(Σ direct + Σ indirect × decay × f_amount, 0, 100) 가설 모델(미검증). 어느 벤더의 공식도 아니다. 교육용 예시로만 사용
"보통 5-hop까지 분석" 공개 근거 없음 — 삭제
벤더별 감쇠계수 λ 표 공개 근거 없음 — 삭제

같은 주소라도 벤더마다 점수가 다를 수 있다는 점만은 분명합니다. 산정 방식이 비공개이기 때문입니다.

Risk Score

정의: KYC 정보 + 노출도 + 거래 패턴을 종합한 회사 내부 점수.

  • 임계값과 등급은 회사 위험평가로 정하고, FATF 2021 para 278에 따라 정기 재검토한다.
  • 벤더 점수는 원료이고 판단은 회사 책임이다. 판단 근거(어떤 룰·어떤 노출)가 케이스 기록에 남아야 업무규정 제79·80조의 분석·보존 요건을 충족한다.

5. KYC vs KYT — 한눈에

구분 KYC KYT(거래모니터링)
대상 사람 거래·지갑
시점 Onboarding 위주 + 주기적 상시
데이터 소스 신분증·PEP DB 공개 블록체인 + 라벨 DB + 내부 원장
규제 용어 고객확인(CDD) transaction monitoring / 거래모니터링체계
핵심 도전 위변조, deepfake, 합성신원 귀속 한계, 클러스터링, 크로스체인

두 시스템이 결합돼야 하는 이유

KYT만 있고 KYC가 부실하면 "주소는 위험한데 그 뒤 사람은 누군지 모름" → STR 작성이 어렵습니다. KYC만 있고 KYT가 부실하면 고객 지갑의 제재 노출을 모릅니다. FATF Red Flag 58개 지표 중 송수신인(19개)·자금원(8개) 범주는 대부분 KYC·행위 신호여서, 온체인 분석만으로는 덮이지 않습니다(FATF Red Flag Indicators).

실무 포인트

KYC 팀과 거래모니터링 팀이 분리돼 있어도 공통 케이스 관리에서 분석가가 고객 KYC와 노출을 한 화면에서 보게 하는 것이 목표입니다.

6. 산출물 3축 — Risk Engine 출력을 한 줄로 그리면 안 되는 이유

이전 판은 Risk Engine 출력을 ALLOW / EDD / STR / BLOCK 한 축으로 그렸습니다. 그러나 한국에서 "BLOCK(차단)"과 "STR"은 근거 법률·절차·수령기관이 전부 다릅니다. 공통 피처·라벨 DB와 케이스 관리는 공유하되, 산출물 축은 셋으로 나눠야 합니다(fds 도시에 §1-A).

실무에서 가장 위험한 것은 탐지 실패보다 분류 실패 — 탐지한 신호를 틀린 출구로 보내는 오류입니다. 케이스 화면에 "어느 제도의 건인가"를 첫 필드로 두고, 한 사건이 두 출구에 해당하면(예: 사기 피해금이 세탁되는 흐름) 각각의 산출물을 따로 남깁니다.

8. 실무 운영 포인트

알람 품질

룰이 너무 느슨하면 알람이 쌓여 검토가 밀리고, 너무 빡빡하면 정상 거래가 묶입니다. FATF 2021 para 276은 운영 룰의 무결성을 정기 검증하라고 요구합니다. "룰 튜닝이 운영의 90%" 같은 비율은 근거가 없어 삭제했습니다.

False Positive vs False Negative

  • FP(오탐): 정상 거래에 알람 → 검토 비용, 고객 불편
  • FN(미탐): 실제 자금세탁 통과 → 규제 위반

한국 실제 제재 사례로, FIU는 2025-11-06 두나무에 과태료 352억원을 결정했고 사유는 고객확인·거래제한·의심거래보고 등의 위반이었습니다(FIU 보도자료 KDI 미러).

"의심되면 차단 먼저, 해제는 사후"는 AML의 운영 원칙이 아닙니다. AML의 산출물은 STR·EDD·거래거절이고, 이용자 자산을 묶는 조치에는 별도 법적 요건이 있습니다.

  • 보이스피싱 임시조치(통신사기피해환급법 §2의5): 금융회사등(거래소 포함, 2026-10-01~)은 "자체점검을 상시적으로 실시"해 피해의심거래계좌등으로 추정되면 이체·출금·가상자산 이전을 지연·일시정지해야 하고, 즉시 통지·본인확인 후 해당 없으면 해제하며, 통지·해제·본인확인 내역을 보존해야 합니다.
  • 임의적 입출금 차단 제한(가상자산이용자보호법 §11): 정당한 사유 없이 이용자의 가상자산 입출금을 차단해서는 안 되고, 차단 시 사유 통지·금융위 보고가 따릅니다. 허용 사유는 시행령 §17에 열거돼 있습니다.

따라서 "차단"을 운영 철학으로 두지 말고, 어떤 법적 절차에 따른 조치인지(임시조치 / 제재 이행 / 거래거절)를 케이스마다 명시해야 합니다.

사람 + 기계

FATF 2021 para 276은 자동화를 허용하되 플래그된 거래는 "human/expert analysis"를 거치라고 요구합니다. 벤더들이 알람 자동 기각·에스컬레이션 기능을 내세우기 시작했지만, 자동 기각을 어디까지 허용할지는 감독기관이 정한 기준이 없습니다. 자동 처리 범위와 사람 승인 지점을 정책에 명시하세요.

공개 벤치마크의 부재

알람→SAR 전환율의 공개 벤치마크는 은행권 EY 2018 EMEIA 조사(리테일 평균 14%)뿐이며, 가상자산 전용 alert-to-STR 벤치마크는 존재하지 않습니다(B)(EY 2018). 흔히 인용되는 "오탐 90~95%"는 정의가 통일되지 않은 2차 수치입니다.

이 논문들을 실무에서 어떻게 쓰나

  • 벤더 평가·RFP: "정확도 몇 %인가" 대신 ground truth 정의, 클러스터 붕괴 처리, 브리지·방향·자산 유형별 매칭 결과를 물으세요. 근거로 Möser & Narayanan 2022와 크로스체인 실측 3편(§5)을 들 수 있습니다.
  • 감독 질의 대응: 감독기관이 "믹서 노출을 어떻게 측정하는가"라고 물으면, 측정 방법의 한계(Railgun 연구의 5가지 누수원, 익명성 집합 축소)를 함께 설명하는 편이 설득력이 있습니다.
  • 모델 검증: 내부 ML 모델을 보고할 때 F1 하나만 쓰지 말고 PR-AUC와 혼동행렬 원값을 같이 적으세요(Elliptic2 사례).

자주 나오는 오해

  • "논문에 정확도 표가 있다" — 클러스터링 휴리스틱에는 표준화된 정확도 수치가 없습니다(CTR:00007).
  • "Monero는 완전 추적 불가" — 2019~2023년 지갑 버그 구간은 부분 추적이 가능했고, 2023년 패치 이후 거래는 그 방법이 통하지 않습니다.
  • "GNN이 있으면 룰이 필요 없다" — Weber 2019에서도, 2026년 재평가(Akter 외, B)에서도 트리 앙상블이 그래프 모델을 앞섰습니다. 감독기관은 해석 가능한 근거와 사람 검토를 요구합니다.
