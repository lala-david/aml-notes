Blockchain Analytics — 온체인 분석 기법

KYT의 **기술적 기반**. 어떻게 익명 주소를 분석하는가. 이 글을 읽고 나면 블록체인 분석 도구가 어떤 휴리스틱과 데이터 위에서 돌아가는지, 그리고 그 결과의 정확도에 대해 **공개적으로 말할 수 있는 것과 없는 것**이 무엇인지 구분할 수 있습니다..

Weber 2019·Elliptic++·Elliptic2의 수치와 브리지 정확도 표, Monero 서술도 원문에 맞게 고쳤습니다. 근거는 research/2026-10-academic-literature.md §8과 정본 보고서 부록 A-38·A-39입니다.

TL;DR

  • 블록체인 분석의 두 축: Clustering(주소 묶기) + Attribution(주소→엔티티 매핑). 그 위에 노출도(exposure) 산정이 올라간다.
  • 핵심 휴리스틱: Common Input Ownership(CIOH), Change Detection, Deposit Heuristic. 이 휴리스틱들의 표준화된 정확도 수치는 존재하지 않는다. Möser & Narayanan은 초록에서 "current techniques rely on heuristics that have not been rigorously evaluated or optimized"라고 썼다(arXiv 2107.05749).
  • Bitcoin(UTXO 모델)과 Ethereum(Account 모델)은 분석법이 다르다.
  • 크로스체인 추적은 2025년에 "휴리스틱"에서 "자동 매칭 시스템"으로 넘어갔다. 다만 연구마다 브리지 집합·정의가 달라 수치를 서로 비교할 수 없다.
  • 프라이버시 프로토콜은 "추적 불가/가능" 이분법이 아니라 익명성 집합 축소율·비트 손실로 측정된다. Monero도 2019~2023년 지갑 버그 구간은 부분 추적이 가능했다.
  • 한계: 새 mixer·브리지의 라벨링 지연, off-chain(CEX 내부) 거래, 공개 벤치마크와 실운영 사이의 격차.

1. 두 축 — Clustering + Attribution, 그리고 노출도

블록체인 분석이 답하려는 두 질문

  1. 이 주소들이 같은 사람인가? → Clustering
  2. 이 클러스터는 누구인가? → Attribution

이 둘이 합쳐져야 "주소 0x...가 누구"를 말할 수 있습니다. Clustering은 알고리즘에 가깝고, Attribution은 데이터·OSINT·협력 관계에 의존합니다. 알고리즘은 논문으로 공개돼 있지만 라벨 데이터는 각 회사가 따로 쌓기 때문에, 분석 결과의 차이는 대부분 라벨에서 나옵니다.

마지막 단계의 출력은 "판정"이 아니라 사람이 검토할 알람입니다. FATF 2021 RBA 가이던스 para 276은 대량 거래에서는 자동화 시스템이 유일한 현실적 수단일 수 있지만 "flagged transactions should go through human/expert analysis"라고 요구합니다(FATF 2021 RBA 가이던스).

Clustering (구조 분석) + Attribution (라벨 데이터) → Exposure (노출도) → 사람 검토

2. 주요 클러스터링 휴리스틱

A. Common Input Ownership Heuristic (CIOH) — Bitcoin

한 트랜잭션의 여러 input 주소 = 같은 사람이 통제.

UTXO 모델 비트코인에서는 한 트랜잭션이 여러 UTXO를 input으로 소비합니다. 각 input을 소비하려면 해당 UTXO의 private key로 서명해야 하므로, 같은 트랜잭션에 모인 input들은 같은 개인키 소유자가 통제한다고 추정합니다.

왜 강력한가: 한 사용자가 주소를 여러 개로 쪼개도, 여러 UTXO를 합쳐 보내는 순간 그 주소들이 한 클러스터로 묶입니다.

예외·한계: CoinJoin(Wasabi, Samourai, JoinMarket) 같은 협력 소비는 서로 다른 엔티티가 의도적으로 input을 합치는 것이라 CIOH가 오작동합니다. 그래서 CIOH를 적용하기 전에 CoinJoin 형태의 트랜잭션을 먼저 걸러냅니다.

2.A Common Input Ownership Heuristic — 엄밀 정의

알고리즘:

def common_input_ownership(tx: Transaction) -> set[Address] | None:
    if len(tx.inputs) < 2:
        return None
    if is_coinjoin(tx):   # 2.B 참조
        return None
    return {inp.address for inp in tx.inputs}

전제: Bitcoin UTXO에서 여러 input을 한 tx에 소비하려면 각 input의 private key에 접근해야 함 → "소유자 동일"이라는 통계적 가정.

엄밀한 한계: - UTXO 모델에서만 성립. Ethereum Account 모델에는 적용 불가(from 주소가 항상 1개). - CoinJoin(의도적 input 합치기)은 가정 위반. - Custodial 거래소 hot wallet은 여러 고객 자금을 한 tx에 합침 → "거래소"라는 엔티티로는 맞지만 "고객"까지 맞지 않음.

정확도 — 표준화된 수치가 없다

이 자리에 있던 "실증 정확도" 표(Meiklejohn 2013·Weber 2019·Möser & Böhme 2017·Bellei 2024 출처)는 삭제했습니다. 표의 수치는 귀속된 논문에 없습니다(CTR:00007). 특히 Weber 2019와 Bellei 2024는 주소 클러스터링 논문이 아니라 거래·서브그래프 분류 논문입니다.

공개 문헌에서 확인되는 것은 다음 정도입니다.

  • Möser & Narayanan(FC 2022)은 기존 기법이 엄밀히 평가·최적화되지 않았다고 명시합니다(arXiv 2107.05749).
  • 같은 논문은 거스름 휴리스틱 26개 변종을 평가했고, 개별 휴리스틱의 진양성률은 "Most achieve true positive rates between 10-30%"였습니다. 랜덤포레스트 결합 모델은 FPR 0.1%에서 TPR 82%(임계값 투표 방식 37%)로 개선됐습니다(B, 본문 수치는 저장소 wave1 검증).
  • 같은 논문에서 제약 없는 거스름 병합은 Mt.Gox 클러스터를 2억 2,400만 주소(+1596%)로 부풀렸습니다. 클러스터 붕괴(cluster collapse)가 정확도 숫자보다 더 중요한 실무 위험입니다(B).

정확도는 데이터셋·시기·지갑 소프트웨어 구성에 따라 달라집니다. 벤더 PoC에서는 "정확도 몇 %"보다 ground truth를 무엇으로 잡았는지, 클러스터 붕괴를 어떻게 탐지하고 되돌리는지를 물어야 합니다(curriculum/day_30.md 참조).

2.B CoinJoin Fingerprint Detection (CIOH 전 필터)

문제: Wasabi·Samourai Whirlpool·JoinMarket 같은 CoinJoin은 서로 다른 사용자가 의도적으로 input을 합칩니다. CIOH 단독 적용 시 오분류가 납니다.

Fingerprint 탐지 규칙 (교육용 예시) — 특정 벤더의 구현이 아니며, 아래 상수는 이 노트가 검증하지 않은 자리표시자입니다.

def is_coinjoin(tx: Transaction) -> bool:
    # 1. Input 수 ≥ 2 (최소 조건)
    if len(tx.inputs) < 2:
        return False
    # 2. Output 동일 금액 클러스터 검출
    amounts = [o.value for o in tx.outputs]
    uniform_outputs = [a for a in amounts if amounts.count(a) >= 3]
    if not uniform_outputs:
        return False
    # 3. 지갑별 고정 denomination 대조
    #    값은 지갑·버전마다 다르다 — 각 지갑의 공개 문서로 확인한 뒤 채울 것
    KNOWN_DENOMS: set[int] = load_wallet_denominations()
    if any(a in KNOWN_DENOMS for a in uniform_outputs):
        return True
    # 4. Input/Output 수가 대칭인 구조
    if len(tx.inputs) >= 5 and len(tx.outputs) >= 5:
        if abs(len(tx.inputs) - len(tx.outputs)) <= 1:
            return True
    return False

결합 정확도: 이전 판의 "CIOH 단독 0.75 / Fingerprint 필터 후 0.95 / ML 분류기 0.97(벤더 추정)" 표는 출처가 없어 삭제했습니다. 공개 근거 없음.

참고: - Meiklejohn et al. (2013) "A Fistful of Bitcoins: Characterizing Payments Among Men with No Names" (ACM IMC 2013) - Möser & Böhme (2017) "Anonymous Alone? Measuring Bitcoin's Second-Generation Anonymization Techniques" (IEEE EuroS&PW 2017, DOI 10.1109/eurospw.2017.48) - Möser & Narayanan (2022) "Resurrecting Address Clustering in Bitcoin" (FC 2022, arXiv 2107.05749)

B. Change Detection (거스름돈 식별)

UTXO 모델에서 거스름돈(change)은 새 주소로 반환됩니다. 이 거스름돈 output을 원 주소 소유자와 같은 클러스터로 묶는 기법.

휴리스틱 예: - "optimal change": 입력이 2개 이상인 거래에서 어떤 출력이 모든 입력값보다 작으면 그 출력이 거스름일 가능성이 높다(Möser & Narayanan 정의, B) - 주소 타입 일치, 반올림 금액, 지갑 지문(트랜잭션 버전·locktime·RBF·스크립트 타입 등)

정확도: 이전 판의 "약 60~80%"는 출처가 없어 삭제했습니다. 위 논문 기준으로 개별 휴리스틱은 대체로 TPR 10~30% 수준이라 단독으로 쓰지 않고 결합합니다(B).

C. Deposit Heuristic (거래소 입금 식별)

배경: 거래소는 고객별로 입금 주소를 따로 발급합니다. 거래소는 입금된 자금을 주기적으로 consolidation 주소로 모아 핫월렛·콜드월렛을 관리합니다. 이 흐름을 따라가면 거래소 주소 체계가 드러납니다.

결과: 거래소 attribution의 핵심 방법. "이 주소에서 나가는 consolidation 흐름이 알려진 거래소 핫월렛으로 흐른다 → 이 주소는 그 거래소의 입금 주소" 식의 추론. 단, 입금주소 재사용·스윕 패턴 기반 식별의 정밀도를 공개 ground truth로 평가한 2025~2026 논문은 확인되지 않았습니다(academic §3-6).

D. Behavior-based Clustering (행동 기반)

  • 시간대, 금액, 거래 빈도 패턴이 비슷한 주소들
  • ML 기반
  • 약한 신호지만 다른 휴리스틱과 결합 시 유용

E. Multi-input Heuristic for Ethereum (계정 모델)

Ethereum은 UTXO가 아닌 Account 모델이라 CIOH를 직접 적용할 수 없습니다. 대신 다음 패턴을 활용합니다.

  • 같은 EOA(Externally Owned Account)가 여러 contract와 상호작용하는 패턴
  • Smart contract 호출 패턴 (funding relationship)
  • Gas 지불 주소 분석 (누가 ETH로 가스비를 내는가)
  • 같은 ENS 도메인 사용

2025년 연구는 계정 모델에서 방향·시간 피처와 거래 텍스트화로 이 공백을 메우려 합니다. DiT-SGCR은 방향성 시간 집계와 미분가능 클러스터링을 결합한 비지도 인코더로, 3개 데이터셋에서 기존 SOTA 대비 F1 3.62~10.83%p 향상을 보고했습니다(arXiv 2506.20123). KGBERT4Eth는 거래 언어모델과 지식그래프를 결합해 피싱 탐지 F1 8~16%p, 비익명화 6~26%p 개선을 보고했습니다(arXiv 2509.03860). 두 편 모두 동료심사 전 프리프린트이고 개선폭만 보고합니다.

용어: - EOA (Externally Owned Account) — 사용자가 private key로 통제하는 Ethereum 계정. - UTXO (Unspent Transaction Output) — Bitcoin의 미사용 거래 출력. 비트코인의 기본 단위.

실무 포인트

Ethereum은 Bitcoin보다 클러스터링이 구조적으로 더 어렵습니다. CIOH 같은 강한 구조 신호가 없기 때문입니다. 그래서 Ethereum 쪽 결과는 라벨 데이터(Attribution)에 더 크게 의존한다고 기억하면 됩니다. 체인별 정확도를 수치로 비교한 공개 벤치마크는 없습니다.

3. Attribution — 주소를 누구에게 매핑하나

데이터 소스

Attribution은 "알고리즘"이 아니라 "데이터 누적"의 문제입니다.

소스 예시
자체 거래 분석회사가 거래소에 입금해 주소 라벨 확보
공개 정보 거래소가 공개한 hot/cold wallet 주소
다크넷 마켓 운영 관찰로 주소 라벨링
법집행 정보 압수·체포로 노출된 주소
제재 목록 OFAC SDN 등 정부 발표 주소
Smart Contract 분석 컨트랙트 deployer, 함수 호출 패턴
소셜 / OSINT 소셜미디어·메신저에서 주소 노출

라벨 카테고리 (일반적 예시)

  • Exchange · DEX · Mixer · Sanctions · Stolen Funds · Ransomware · Darknet Market · Scam · Gambling · Mining Pool · High-risk Jurisdiction Exchange · ATM · Merchant Service

실무 포인트

라벨 데이터의 한계는 감독기관 문서에도 적혀 있습니다.

  • FATF 2021 RBA 가이던스 para 234: "There is a cost consideration with these tools and not all VAs are covered by all vendors." 프라이버시·데이터보호 영향도 고려하라고 합니다(FATF 2021).
  • NYDFS 산업서한(2022-04-28)은 지원하는 자산마다 추적 절차를 갖추라고 요구하고, 외부 서비스와 자체 개발 도구를 모두 허용합니다. 분석 도구가 "may not be able to identify underlying owners"라는 한계도 명시합니다(NYDFS).
  • FATF 7차 Targeted Update(2026-07-16)는 MIVA 표 검증에 "blockchain analytics companies' data"를 썼다고 밝히면서도, 그 데이터가 관할의 불법금융 위험 평가에 기반한 것은 아니라고 단서를 답니다(FATF 7차 TU).

벤더별 지역·분야 강점을 비교한 공개 평가는 확인되지 않았습니다. 커버리지는 PoC에서 자사 지원 자산 목록을 기준으로 직접 확인해야 합니다.

4. Exposure Score — 개념과 공개 근거의 한계

4.1 정의

노출도(Exposure): 한 주소(또는 클러스터)가 위험 엔티티(제재 대상·믹서·다크넷 등)와 어떻게 연결돼 있는지를 정량화한 값.

  • Direct: 분석 대상이 위험 엔티티와 직접 거래
  • Indirect: 중개 주소를 거쳐 도달

간접 노출을 보는 규범적 근거는 FATF 2021 RBA 가이던스 para 277입니다. 고위험 상황의 강화 모니터링은 "extend beyond the immediate transaction between the VASP or its customer or counterparty"여야 하고, 기준·임계값은 "reviewed on a regular basis"여야 합니다(FATF 2021). FATF 7차 TU는 VASP가 "transactions monitoring and blockchain analytics tools"로 급속 이전을 탐지하고, 프로토콜·브리지·믹서·크로스체인 도구에 대한 노출을 평가하라고 권고했습니다(FATF 7차 TU).

4.2 공식에 대해 말할 수 있는 것

이전 판에는 "벤더 일반화 공식", 카테고리별 가중치 표, 벤더별 감쇠계수 λ 표, "보통 5-hop까지"라는 서술과 그 계산 예시가 있었습니다. 모두 공개 근거가 없어 삭제했습니다(정본 보고서 부록 A-37, kyt 도시에 §9 #8).

2026-10-21 기준 이 저장소의 조사에서 홉 수 상한·감쇠함수·카테고리 가중치를 공개한 벤더 자료는 확인되지 않았습니다. 따라서 노출도 점수는 재현할 수 없는 블랙박스로 다뤄야 합니다. 구조만 적으면 다음과 같습니다. 계수는 일부러 비워 둡니다.

4.3 점수 다음 단계 — 자동 STR이 아니다

이전 판의 계산 예시는 "64점 → BLOCK + STR 자동 발동"으로 끝났습니다. 이것은 틀린 연결입니다. 노출도 점수는 차단·통보·STR 판단의 입력일 뿐입니다. 한국 「자금세탁방지 및 공중협박자금조달금지에 관한 업무규정」은 제76조~제81조에서 거래모니터링체계와 보고체제를 규정하고(법제처), FATF는 플래그된 거래의 사람 검토를 요구합니다. 산출물을 차단/통보/STR 세 축으로 나누는 설계는 kyc-kyt.md를 보세요.

이전 판의 "KYT 점수 그대로 차단하면 FP 30~50%", "목표 FP 5%·FN 1%", override 계수표도 출처가 없어 삭제했습니다.

4.4 한계

  1. 노출도는 과거 라벨 기반 → 새 라벨이 반영되기까지 지연이 있습니다(지연 기간을 측정한 공개 자료는 확인되지 않음).
  2. 간접 노출을 깊이 따라갈수록 무관한 주소가 섞입니다. 깊이를 어디서 끊는지가 공개돼 있지 않다는 점이 설명 가능성의 문제입니다.
  3. 프라이버시 프로토콜 진화 → Railgun 같은 shielded pool은 §7.5의 측정 연구를 보세요.
  4. Cross-chain → 브리지 매칭이 따로 필요합니다(§5).

실무 포인트

노출도 공식은 벤더마다 다르고 공개되지 않습니다. 이게 STR 작성 시 "왜 이 점수인가"를 설명하기 어려운 원인입니다. 대응은 벤더에게 카테고리별 하위 점수와 추적 경로를 받아 사내 정책 언어로 다시 쓰는 것입니다. FATF 2021 para 276이 "operating rules"를 이해하고 무결성을 정기 검증하라고 요구한다는 점을 근거로 들 수 있습니다.

5. Cross-chain Tracing — Bridge Matching

도전

한 체인에서 끊어진 흐름이 다른 체인에서 시작되는 구조. 중간에 wrapped 토큰화(A 체인의 ETH가 B 체인의 wETH로)로 같은 가치지만 다른 형태가 됩니다.

5.1 문제 정의

Ethereum → Polygon → Arbitrum → Optimism 간 자산 이동은 bridge contract를 거칩니다. 각 체인의 tx는 독립적이므로, 추적을 이어 가려면 "bridge event를 체인 간 연결"해야 합니다. 2025년 연구(ConneX)는 브리지 양측 거래 쌍 매칭 실패가 자금 추적 실패의 주원인이라고 문제를 정의했습니다(arXiv 2511.01393).

5.2 Bridge 이벤트 구조 (참고)

이벤트명·필드는 각 브리지 컨트랙트 버전마다 다를 수 있으므로 실제 구현 전에 컨트랙트 ABI로 확인하세요.

5.3 매칭 알고리즘 (교육용 예시)

time_window·amount_tolerance 기본값은 예시입니다. 실측 연구(§5.5)에서는 입금과 출금의 시간창이 크게 달랐습니다.

def match_bridge_events(
    lock_events: list[LockEvent],
    mint_events: list[MintEvent],
    time_window: int,          # 초 — 브리지·방향별로 따로 정한다
    amount_tolerance: float,   # 수수료 차감 토큰은 별도 처리
) -> list[tuple[LockEvent, MintEvent]]:
    matches = []
    for lock in lock_events:
        candidates = []
        for mint in mint_events:
            if mint.token_canonical != lock.token_canonical:
                continue
            if abs(mint.timestamp - lock.timestamp) > time_window:
                continue
            if abs(mint.amount - lock.amount) / lock.amount > amount_tolerance:
                continue
            # 순번(nonce) 필드가 양쪽에 있으면 결정적 매칭
            if hasattr(lock, 'nonce') and hasattr(mint, 'nonce'):
                if lock.nonce == mint.nonce:
                    candidates = [mint]
                    break
            candidates.append(mint)
        if len(candidates) == 1:
            matches.append((lock, candidates[0]))
        elif len(candidates) > 1:
            # 금액 차이 최소 선택 (차선책 — 오매칭 위험 기록)
            best = min(candidates, key=lambda m: abs(m.amount - lock.amount))
            matches.append((lock, best))
        # 0개: 목적지 체인에 아직 도착 안 함 — 재큐잉
    return matches

5.6 한계

  • 여러 브리지를 연달아 거치면 단계마다 오류가 누적됩니다. 이전 판의 "3-hop ≈ 0.73" 계산은 출처 없는 단일 브리지 수치를 곱한 것이라 삭제했습니다.
  • 비표준 경로(중앙화 OTC·P2P)는 온체인 브리지 이벤트가 없습니다.
  • THORChain·Across 같은 유동성 풀 기반 브리지는 sender-receiver가 1:1로 연결되지 않습니다.
  • DeFi 거래의 의미 해석이 병목입니다. AMLGuard는 DeFi 거래를 "DeFi Semantic Unit"으로 추상화해, 실제 세탁 사건 82건에서 목적지 정밀도 94.4%(단일체인)/87.6%(크로스체인)를 보고했습니다(arXiv 2607.18869). 알려진 사건만 쓴 평가라 선택 편향이 있습니다.

실무 포인트

FATF 7차 TU가 브리지·크로스체인 도구 노출 평가를 명시했으므로, 크로스체인 추적은 선택 기능이 아니라 위험평가 항목입니다. PoC에서는 자사가 지원하는 체인 조합으로 실제 경로를 여러 개 만들어 복원 여부를 직접 확인하고, 결과를 브리지·방향·자산 유형별로 기록하세요. 단일 정확도 숫자로 요약하지 않는 것이 핵심입니다.

7. 분석 도구의 데이터 파이프라인

  1. Node Operation — Bitcoin Core, Geth, Erigon, Reth 등. 전체 이력이 필요하면 archive node.
  2. Indexing — 트랜잭션을 그래프 저장소에 적재, 주소 ↔ 트랜잭션 매핑.
  3. Heuristic Clustering — CIOH·Change Detection·Deposit 휴리스틱으로 클러스터 ID 부여. 병합 제약과 붕괴 점검을 둡니다(Möser & Narayanan의 지출-출력 제약 사례, B).
  4. Attribution — 라벨 DB(자체 + 외부)로 클러스터 → 엔티티 매핑.
  5. Risk Scoring — 노출도 계산.
  6. API / UI — 외부 API, 분석가용 시각화. 출력은 사람 검토로 갑니다.

실무 포인트

노드 운영과 인덱싱은 체인마다 따로 해야 해서 지원 체인이 늘수록 부담이 커집니다. 그래서 자체 노드와 외부 API를 함께 쓰는 구성이 흔합니다. 이전 판의 인프라 용량·비용 수치는 출처가 없어 삭제했습니다.

  • 거래·서브그래프 분류: Elliptic(거래 노드), Elliptic2(서브그래프)
  • 믹서 계정 연결: §7.5
  • 피싱·rug pull 탐지: PhishEye는 자기지도 방식으로 실배포에서 미지의 피싱 주소 1,803개를 찾았습니다(arXiv 2605.01207). RugScreener는 균형 데이터(500/500)에서 균형 정확도 95.7%를 보고했습니다(IEEE TIFS 2025).

공개 벤치마크가 실제로 말하는 것

  • Weber et al. 2019(Elliptic 공개 논문)에서 최고 성능은 GNN이 아니라 랜덤포레스트였습니다. 불법 클래스 기준 RF(전체 피처+노드 임베딩) precision 0.971 / recall 0.675 / F1 0.796, GCN 0.812 / 0.512 / 0.628(arXiv 1908.02591, 본문 수치 B). 이전 판의 "RF 0.93/0.77/0.84, GCN 0.92/0.83/0.87"은 논문과 다릅니다.
  • 같은 논문에서 시점 43의 다크마켓 폐쇄 이후 모든 모델의 성능이 급락했습니다(B). 개념 표류(concept drift)가 운영 위험의 본질입니다.
  • Elliptic2의 GLASS 모델은 F1 0.933이지만 PR-AUC 0.208, 혼동행렬 TP 245 / FP 765 — 의심으로 예측한 4건 중 약 1건만 실제 의심입니다(B)(arXiv 2404.19109). 극단적 불균형에서 F1만 보면 오독합니다.
  • Elliptic 시계열 분할에서 Extra Trees AUPRC 0.570 vs GraphSAGE 0.311로 트리 앙상블이 앞섰습니다(B)(Akter 외 2026).
  • GCN·GAT·GraphSAGE의 Elliptic 결과는 가중치 초기화·정규화 선택만으로 달라집니다(arXiv 2602.23599). 논문 간 F1 비교표를 만드는 것 자체가 위험합니다.
  • TransXion(KDD '26)은 템플릿 기반 이상 주입 벤치마크가 모델 강건성을 과대평가한다고 보였습니다(arXiv 2604.17420).

한계

  • 라벨 데이터 부족 — 각 회사가 자체 보유하고 공개하지 않습니다. Elliptic·Elliptic2 이후 자금세탁 라벨 Bitcoin/Ethereum 데이터셋의 신규 공개는 2026-10-21 기준 확인되지 않았습니다(academic §3-11).
  • Adversarial behavior — 분석을 회피하는 패턴(분할 금액, 무작위 시간). 경제적 동기를 가진 공격자를 모델링한 연구는 사실상 공백입니다.
  • 모델 설명가능성 — 규제 보고 시 "왜 STR 보고했나"를 설명해야 합니다. 근거 인용을 강제한 LLM 트리아지 연구는 인용 유효성 0.98인데 에스컬레이션 F1은 0.62였습니다(합성 데이터)(arXiv 2604.19755). 근거를 잘 인용한다고 판단이 맞는 것은 아닙니다.

실무 포인트

ML 탐지는 보조 수단으로 쓰는 게 안전합니다. 감독 검사에서 "이 고객은 어떤 근거로 STR 대상이 됐나"에 "모델이 그렇게 판단했다"는 답이 될 수 없습니다. 공개 근거로 보면 그래프 모델의 실무 우위는 확인되지 않았고, 트리 앙상블과 운영 지표(PR-AUC, 혼동행렬 원값)로 먼저 검증하라는 것이 2026년 문헌의 공통 메시지입니다.

9. 자체 구축 vs 벤더 활용

규제가 허용하는 것

  • NYDFS(2022-04-28): 외부 서비스와 자체 개발 도구 모두 허용, 다만 자산별 추적 절차와 역할 분담을 문서화하라고 요구(NYDFS).
  • FATF 2021 para 156(c)는 EDD 수단으로 블록체인 분석을 들고, para 323(g)는 일본 JFSA가 "whether blockchain analysis tools are used for transaction monitoring and/or risk analysis purposes"를 감독 KPI로 수집한다고 적었습니다(FATF 2021).

판단 기준

  • 벤더: 라벨 DB·다체인 커버리지를 바로 얻습니다. 대신 노출도 공식이 비공개라 설명 책임이 남습니다.
  • 자체 구축: 사내 데이터와 결합하고 국내 특화 라벨을 쌓을 수 있습니다. 대신 노드·인덱싱·라벨링을 직접 감당합니다.
  • 대부분은 외부 분석 도구 + 자체 보완 모듈의 조합입니다. 특정 거래소가 어느 벤더를 쓰는지는 공개 확인된 범위가 좁으므로 일괄 서술하지 않습니다.

실무 포인트

"자체 구축 vs 벤더"의 답은 비용보다 규제 대응 근거로 봐야 합니다. 어느 쪽이든 감독기관 앞에서 필요한 것은 같습니다. 지원 자산별 추적 절차, 룰·임계값의 정기 검토 기록, 플래그 거래의 사람 검토 기록입니다.

10. 한계와 미래

한계

  • Privacy coin(Monero): 2023년 패치 이후 거래에는 알려진 버그 기반 휴리스틱이 통하지 않습니다(§7.5). 패치 이전 구간은 부분 추적이 가능했습니다.
  • 새 mixer·새 bridge: 라벨링 지연. 지연 기간을 측정한 공개 자료는 확인되지 않았습니다.
  • Off-chain(CEX 내부 거래): 보이지 않습니다.
  • 관할 귀속: 가명 주소에는 지리 식별자가 없어 단일 관할 내 온체인 활동을 측정하기 어렵습니다. ECB CAMEG는 2026년 계획에 지리적 위치 식별 방법론·지표 개발을 넣었습니다(ECB OP 382).

미래 방향

  • 서브그래프·경로·의도 추적: 거래 하나가 아니라 자금 흐름 전체를 탐지 단위로 삼는 쪽(§12).
  • Cross-chain analytics 표준화: 공통 벤치마크가 아직 없습니다.
  • ZKP 적용 — 프라이버시와 컴플라이언스 양립. SSI·ZKP·속성기반 접근제어로 KYC 준수 dApp의 온체인 권한부여를 구현한 연구(arXiv 2510.05807), 중앙은행 전문가의 PET 분류(BIS Innovation Hub Mandala 예시, ECB OP 382 §2.10.2)가 있습니다.

실무 포인트

ZKP 기반 프라이버시-컴플라이언스 양립은 장기 방향입니다. 2026-10-21 기준 학술 문헌은 설계·분류 단계이고, 감독 실무에서 채택된 사례를 다룬 평가 논문은 확인되지 않았습니다.

요약 부록 — 빠른 참조용

두 축: Clustering (구조) + Attribution (데이터) → 노출도 5대 휴리스틱: CIOH · Change · Deposit · Behavior · Ethereum Multi-input 정확도: 표준화된 수치 없음. 클러스터 붕괴 점검이 더 중요 체인별 차이: Bitcoin UTXO = 구조 신호 있음 / Ethereum Account = 라벨 의존 노출도: Direct / Indirect. 홉 상한·가중치·감쇠는 비공개 → 블랙박스로 취급

💼 실무 현장 (Industry Reality)

이전 판의 벤더 매출 비중·조달액·인력 규모·노드 비용·"KYT 벤더별 강점 PoC 비교"·국내 거래소별 사용 벤더·"자체 구축 실패" 사례는 모두 공개 출처가 없어 삭제했습니다.

감독기관이 블록체인 분석에 대해 실제로 쓴 문장

  • FATF 7차 TU(2026-07-16) 민간부문 권고: "identify suspicious patterns in VA transactions and detect rapid transfer of VAs using transactions monitoring and blockchain analytics tools." FATF 공식 문서가 VASP 대상 권고에 "blockchain analytics tools"를 직접 쓴 것은 이 조사 범위에서 처음입니다.
  • 같은 문서는 통제 요소로 "KYC, wallet screening, blacklisting, and, where appropriate, whitelisting mechanisms as well as freezing and blocking capabilities"를 열거합니다.
  • 업계 용어 "KYT"는 FATF 7차 TU·2021 RBA 가이던스·2020 레드플래그·MAS PSN02 어디에도 나오지 않습니다. 한국 업무규정의 용어는 "거래모니터링체계"(제76조)입니다.

자주 나오는 오해

  • "CIOH 정확도는 몇 %다" — 표준화된 수치는 없습니다. 숫자를 들었다면 데이터셋·시기·ground truth를 되물으세요.
  • "GNN이 최신이니 더 정확하다" — Elliptic 원논문에서도, 2026년 재평가에서도 트리 앙상블이 앞섰습니다(§8).
  • "Monero는 완전히 추적 불가"/"Monero도 다 추적된다" — 둘 다 틀렸습니다. 시기를 나눠야 합니다(§7.5).
  • "제재하면 믹서는 끝난다" — Tornado Cash 입금은 71.03% 줄었지만 보안사고의 78.33%가 여전히 경유했습니다. "효과 있음/없음" 이분법이 맞지 않습니다.
  • "발행자가 동결하면 자금은 묶인다" — USDT 7.3%, USDC 18.7%의 제재 주소가 동결 전에 전액 인출했습니다. BIS도 발행자 동결·분석업체 지원이 "cannot replace routine, large-scale AML/CFT controls in everyday payments"라고 했습니다(BIS AER 2026).

12. 연구 흐름 2019 → 2026

2025~2026년의 이동을 정본 보고서는 다섯 가지로 요약합니다. (1) 노드 분류 → 서브그래프·경로·의도 추적, (2) 크로스체인 자동 매칭, (3) 프라이버시 프로토콜의 정량 측정, (4) 사기 측정 규모 확대(address poisoning 2.7억 건, arXiv 2501.16681), (5) 벤치마크 회의론. 반대로 트래블룰 효과 실증, LLM의 실데이터 평가, 자기수탁 지갑 소유 검증을 다룬 2025~2026 동료심사 논문은 확인되지 않았습니다. 논문 목록은 ../../deep/papers.md의 2025~2026 섹션을 보세요.

가상자산 자금세탁의 **실제 패턴**. 이 글을 읽고 나면 FATF Red Flag 58개 지표가 거래모니터링 룰의 어떤 원형으로 이어지는지, 9개 고전 유형이 각각 어떤 원리로 작동하고 왜 탐지가 어려운지, 그리고 FATF 7차 TU(2026-07-16)가 새로 지목한 유형이 무엇인지 설명할 수 있게 됩니다..

TL;DR

  • 공식 지표 원천은 FATF Red Flag Indicators(2020-09-14) 다: 6개 범주(거래·거래패턴·익명성·송수신인·자금원/재산원·지리), 상위 지표 58개(5·8·14·19·8·4). 감독 체크리스트로 쓰지 말고(para 20), 지표 하나만으로 의심 근거가 되지 않는다(para 8).
  • 고전 9가지 유형: 믹서 · 체인호핑 · 브리지 · peel chain · DEX swap · DeFi lending · 프라이버시코인 · NFT wash · OTC 환전 — 대부분 Red Flag의 익명성(A)·거래패턴(P) 범주에 대응한다. 송수신인(S)·자금원(F) 범주는 온체인보다 KYC·행위 신호다.
  • 7차 TU(2026-07-16)의 신유형: 동결 회피용 자체 스테이블코인, RPC 노드·멀티시그 공급자 같은 제3자 인프라 공격, 딥페이크 채용사기·AI 익스플로잇, 가스비 조달 은닉, 소매 고객으로 위장한 역외 VASP 계정.
  • 학계가 측정한 사기 유형: address poisoning(Ethereum·BSC 2년간 공격 2.7억 건, 최소 8,380만 달러 손실, USENIX Security '25).
  • 스테이블코인이 2025년 불법 거래량의 84%(Chainalysis 2026-01-08, B).

1. 유형론의 계층 — Red Flag에서 룰까지

공식 지표 원천

FATF 「Virtual Assets — Red Flag Indicators of ML/TF」(2020-09-14)는 2017~2020년 관할이 제출한 100건 이상의 사례로 6개 범주·상위 지표 58개·번호 사례 13건을 정리했습니다(FATF Red Flag PDF). 2026-10-21 현재 유일판이며, 2021년 이후 유형(브리지·DeFi 유동성·드레이너·동결저항 스테이블코인)은 들어 있지 않아 7차 TU와 2026 타겟보고서로 보완해야 합니다.

Red Flag 6범주 → 거래모니터링 룰 원형

룰 원형 분류(임계·속도·구조화·노출·행위·지리)와 지표 ID(RF-T1 등)는 fatf-virtual-asset-reports 도시에 §3A-3의 정리를 따릅니다. 매핑은 해석이며, 지표 원문은 Red Flag PDF에 있습니다.

범주 대표 지표(원문 요지) 룰 원형 주 데이터
T 거래 임계 미만 분할(RF-T1), 24시간 내 다수 고액·규칙 간격(RF-T2), 즉시 다수 해외 VASP 이전(RF-T3), 입금 후 즉시 무거래 출금 "turns the exchange/VASP into an ML mixer"(RF-T4), 도난자금 주소발 입금(RF-T5) 임계·속도·구조화 내부 원장 + 체인
P 거래패턴 프로필 불일치 대액 초기 입금(RF-P1·P2), 다수 무관 지갑 소액 집적 후 일괄 이전(RF-P6), 손실 감수 환전(RF-P7) 속도·구조화·행위 내부 원장
A 익명성 AEC·프라이버시코인 전환(RF-A1·A2), 믹서 이용(RF-A5·A6), 직·간접 노출(RF-A7), Tor·VPN 접속(RF-A10), 동일 IP 다수 지갑(RF-A11) 노출·행위 귀속 DB + 접속 로그
S 송수신인 KYC 미비·자금원 질의 거부(RF-S5), 위조 서류(RF-S7), 프로필 IP 불일치(RF-S9), VA 비숙련 송금인(RF-S12), 고령 고객 다건 거래(RF-S13), 식별정보 빈번 변경(RF-S16), 메모 필드 불법 암시 문구(RF-S18) 행위·KYC KYC·디바이스
F 자금원 사기·랜섬웨어·제재·다크넷 연계 주소(RF-F1), 믹서 직접 유입(RF-F6) 노출 귀속 DB
G 지리 미등록 거래소(RF-G1), 고위험 관할 VASP(RF-G2·G3) 지리 VASP 디렉터리

송수신인(S) 범주가 19개로 가장 큽니다. 즉 Red Flag의 다수는 온체인 구조가 아니라 고객·행위 신호이고, 블록체인 분석 도구만으로는 덮이지 않습니다.

자금세탁 3단계와의 매핑

전통 ML 가상자산 ML 예시
Placement 현금 → 거래소 입금, OTC 매수, P2P 거래
Layering 믹서, 체인호핑, 브리지, DEX swap, peel chain, NFT wash
Integration OTC 환전, 상품권 구매, 고가 자산 결제, 합법 사업체 자금화

가상자산은 단계 사이 간격이 짧을 수 있다는 점이 전통 금융과 다릅니다. Red Flag RF-T4는 입금 직후 무거래 출금이 거래소를 "사실상 믹서로 만든다"고 표현합니다. 이전 판의 "Bybit 사례: 48시간 내 $160M layering 완료"는 출처가 없어 삭제했습니다. Bybit 사건의 공식 수치는 FATF 6차 TU(2025-06-26)의 DPRK 탈취 USD 14.6억, 회수율 3.8% 입니다(6차 TU).

한국 사례

Red Flag Case Study 2는 한국 제출 사례입니다. 피싱 피해금 약 4억원이 3종 가상자산으로 바뀐 뒤 국내 VASP 48개 계정을 거쳐 55회 이전되고 해외 지갑으로 빠져나갔습니다(p.7). RF-T3(즉시 다수 해외 VASP 이전)·RF-P4(설명 없는 다종 자산·다계정)의 전형입니다.

2. 9가지 고전 유형 — 원리·도구·탐지 포인트

A. Mixer / Tumbler (믹서) — RF-A5·A6·F6

원리: 여러 사용자의 자금을 한 풀에 섞은 뒤 출금해 입금 주소와 출금 주소의 온체인 연결을 끊음.

대표 방식: - Tornado Cash (Ethereum) — zk-SNARK 기반 고정 액면 풀. OFAC 제재 후 2025-03-21 SDN에서 삭제(엔티티 1·ETH 주소 90)(OFAC 2025-03-21). 형사 절차는 별개로, 2025-08-06 Roman Storm 무면허 송금업 공모 유죄, 자금세탁·IEEPA 공모는 배심 불일치(B)(Willkie). 제재 효과 측정 연구는 957일간 입금액이 71.03% 줄었지만 Ethereum 보안사고의 78.33%가 여전히 Tornado Cash를 거쳤다고 보고했다(WWW '26)(arXiv 2507.11721). 제재 해제 ≠ 위험 해제. - CoinJoin (Bitcoin) — 여러 사용자가 동시에 균등 금액을 섞는 방식. - Railgun 등 차폐 풀 — 2026 측정에서 출금의 17.65%가 입금과 하나로 연결됐고 중위 익명성 손실은 3.42비트였다(arXiv 2606.25926). "추적 불가/가능" 이분법이 아니라 정량 측정의 대상이다.

탐지 포인트: - 알려진 믹서 컨트랙트 주소 노출 - 액면 표준화(고정 액면 풀) - Input/Output 개수 균등 (CoinJoin 지문) - 믹서 진입 후 체류시간 분포

B. Chain Hopping (체인 점프) — RF-P4·P8

원리: 여러 체인을 넘나들며 흔적을 흐림. 분석 도구가 한 체인에서 끊기는 점을 노림.

FATF 7차 TU는 VASP에 프로토콜·브리지·믹서·크로스체인 도구 노출 평가를 요구했습니다(권고 6-iv)(7차 TU PDF).

C. Cross-chain Bridge 활용

원리: A 체인에서 자금을 잠그고 B 체인에서 wrapped 토큰 발행 → 추적 단절.

이중 리스크: 브리지는 세탁 경로이면서 해킹 표적이기도 합니다. 7차 TU는 DPRK가 탈취 자금을 브리지·언호스티드 지갑·OTC 네트워크로 세탁한다고 적었습니다(para 33). 이전 판의 브리지 해킹 손실 표는 이번 근거 자료로 재확인하지 못해 삭제했습니다.

탐지 포인트: 브리지 컨트랙트 입출금 인덱싱 + 시간·금액 매칭. 2025년 연구는 12개 브리지 양방향 F1 91.75%(ABCTracer), 5개 브리지 약 50만 건 F1 0.9746(ConneX)을 보고했지만, 브리지 집합이 달라 두 수치를 비교할 수 없습니다(arXiv 2504.01822; arXiv 2511.01393).

D. Peel Chain (껍질 사슬) — RF-T1

원리: 큰 금액 주소에서 소액씩 떼어내(peel) 다른 주소로 보내고 잔액은 또 다른 주소로 → 길게 늘어진 사슬.

탐지 포인트: 그래프 분석 — 출력 2개 구조의 반복, 분기 간격, 소액의 상대적 일정성.

E. DEX Swap — RF-P8·A1

원리: KYC 없는 DEX에서 토큰을 교환해 자산 형태를 바꿈.

탐지 포인트: DEX 자체는 합법이므로 swap 자체가 아니라 swap 전후 흐름을 본다.

F. DeFi Lending / Liquidity Pool

원리: 렌딩 프로토콜에 토큰 입금 → 다른 자산으로 인출, 또는 LP 토큰 발행·소각으로 출처 흐림.

규범: FATF 2021 가이던스 para 67은 "A DeFi application (i.e. the software program) is not a VASP"이지만 통제력·충분한 영향력을 가진 사람은 VASP가 될 수 있다고 했습니다. 2026-07-21 DeFi 타겟보고서가 이 분석을 갱신했습니다(FATF DeFi 보고서). 상세는 defi-nft-risks.md.

G. Privacy Coin — RF-A1·A2

원리: 프로토콜 설계로 송수신인·금액을 숨김.

코인 기술 추적 가능성 (공개 연구 기준)
Monero (XMR) Ring Signature + Stealth Address + RingCT 2019~2023 지갑 버그·P2Pool·Mordinal 휴리스틱은 대부분 고정밀이었으나, 2023년 초 패치 이후 신규 거래에는 무효 — 패치 이전 구간은 부분 추적 가능, 이후는 아니다(arXiv 2408.05332)
Zcash (ZEC) zk-SNARK shielded transaction shielded 사용 여부에 따라 다름

규제: EU AMLR(2024/1624) 제79조는 CASP의 익명성강화코인 취급을 금지하며 2027-07-10 적용 예정(enacted-not-in-force) 입니다(EUR-Lex). Red Flag RF-A2는 "투명 체인 자산 → 거래소 → 즉시 AEC 전환"을 지표로 듭니다. 진입·탈출 순간이 탐지 기회입니다.

H. NFT Wash Trading

원리: 자기들끼리 NFT를 사고팔며 가격·거래량을 부풀려 자금 이전을 정당화.

유형: 자기거래(양쪽 지갑 동일인), 순환거래(A→B→C→A), 가격 펌프 후 외부 매도.

규범: FATF 2021 가이던스 para 53 — NFT는 "generally not considered to be VAs"이나 결제·투자 용도로 실사용되면 VA로 볼 수 있습니다. 이전 판의 "wash trading 비중 25~50%"는 이번 근거 자료로 재확인하지 못해 삭제했습니다.

탐지 포인트: 짧은 시간 내 같은 NFT의 반복 거래, 거래자 주소 간 클러스터 관계.

I. OTC Desk · 전문 세탁 네트워크 — RF-A3·G1

원리: 저KYC OTC·비규제 거래소에서 가상자산 ↔ 법정화폐 환전.

공식 사례: - FATF 7차 TU: 캄보디아 소재 금융 복합체가 2021-08~2025-01 최소 USD 40억을 세탁, 그중 최소 USD 3,700만이 DPRK 탈취자금(para 29~30). 스페인 Operation Borrelli(2025-06, EUR 4.6억·피해자 5,000명). - 미국: 2025-10-14 OFAC가 Prince Group을 초국가범죄조직으로 지정(146개 대상), FinCEN이 같은 날 Huione Group §311 최종규칙을 발동(재무부 sb0278).

이전 판의 "CMLN 2025년 $16.1B 처리, 활성 wallet 1,799개", "수수료 5~15%"는 이번 근거 자료로 재확인하지 못해 삭제했습니다.

실무 포인트

룰을 유형별 그룹으로 관리하고 각 룰에 대응하는 RF-ID를 메타데이터로 달면, 알람의 근거를 STR에 쓰기 쉽고 오탐 원인을 역추적하기 쉬워집니다.

3. FATF 7차 TU(2026-07-16)가 지목한 신유형

신유형 내용 위치 거래모니터링 시사점
동결 회피용 자체 스테이블코인 제3자 발행자가 USD 2,900만 이상을 동결하자 범죄 복합체가 "immune to asset freezing"을 내세운 자체 스테이블코인 발행(다중 체인 + 자체 체인). FATF: VASP가 "issuer-level asset freeze/burn mechanisms"에 기댈 수 없을 수도 있다 para 35 발행자 동결을 통제 수단으로 가정하지 말 것. 자체 발행 코인 노출을 별도 카테고리로
제3자 인프라 공격 DPRK가 VASP·DeFi뿐 아니라 RPC 노드·멀티시그 보안 공급자를 공격하고 브리지·언호스티드 지갑·OTC로 세탁 para 33 해킹 직후 급속 이전 탐지(권고 6-ii)
AI 악용 딥페이크 영상 면접 채용사기로 USD 100만 이상 탈취(주로 스테이블코인), AI 코딩 도구·에이전트로 스마트컨트랙트 익스플로잇 생성 para 34 온보딩 딥페이크 대응(RF-S7 확장), 익스플로잇 직후 자금 흐름
TF와 가스비 은닉 ISIL·AQ가 스테이블코인 선호, 주소 로테이션·micro-splitting·multi-hop, Tron 기반 USDT, 가스비 조달 패턴을 숨기는 서비스 para 33·36 소액 분할·주소 로테이션 패턴
소매 위장 역외 VASP 역외 VASP가 소매 고객으로 위장해 계정 사용 권고 6-iii 계정 거래 규모·패턴이 개인 프로필과 맞지 않는지

출처: 7차 TU PDF.

학계도 같은 방향을 측정했습니다. USDT 제재 주소의 7.3%, USDC의 18.7%가 동결 발효 전에 전액 인출됐습니다(arXiv 2603.27739).

Address poisoning은 지갑 단에서 경고가 거의 없으므로, 거래소 출금 시점에 "최근 거래 상대와 앞뒤 자리만 같은 주소"를 확인하는 것이 마지막 방어선이 될 수 있습니다. 이것은 FDS(이용자 보호)의 영역이고, 피해금이 세탁되는 흐름은 AML(STR)의 영역입니다.

5. 2025~2026 흐름

A. 스테이블코인의 비중

  • 2025년 불법 거래량의 84%가 스테이블코인(Chainalysis 2026-01-08, B)(Chainalysis). FATF 2026-03-03 스테이블코인·비수탁지갑 타겟보고서도 같은 수치를 인용합니다(FATF 2026-03-03).
  • 동결 가능성은 양면입니다. 발행자 동결이 작동한 사례도 있지만, 7차 TU는 동결 회피 설계를 경고했습니다(§3).

이전 판의 자산별 비중 차트(스테이블코인 외 BTC·ETH·알트 분할)와 2025 통계 카드(DPRK $2.02B, CMLN $16.1B)는 근거가 확인되지 않은 수치를 포함해 이 문서에서 뺐습니다.

B. 국가 단위 제재 회피망

  • Chainalysis는 러시아 루블 스테이블코인 A7A5가 1년 미만에 USD 933억 이상 거래됐다고 보고했습니다(B)(Chainalysis). TRM은 제재 주체·관할 유입 USD 930억 중 A7A5를 약 720억으로 추정했습니다(B)(TRM).
  • 미국 FinCEN은 2026-10-05 A7 네트워크의 역외 하위대리인과의 자금이체를 금지하는 특별조치 NPRM(RIN 1506-AB77)을 냈습니다(proposed)(Federal Register 2026-20371). 같은 날 믹싱 §311 NPRM은 철회됐습니다(withdrawn). 규제의 대상이 "유형"에서 "네트워크"로 옮겨 갔습니다.

C. DPRK

  • FATF 6차 TU: Bybit 탈취 USD 14.6억, 회수율 3.8%.
  • Chainalysis: 2025년 DPRK 연계 해커 탈취 약 USD 20억(Bybit 약 15억 포함)(B).
  • FATF 7차 TU: 제3자 인프라(RPC 노드·멀티시그 공급자) 공격, 캄보디아 복합체 경유 USD 3,700만.

이전 판의 "2025년 $2.02B 탈취, 누적 $6.75B"는 출처가 확인되지 않아 위 수치로 바꿨습니다.

D. 산업화

7차 TU가 다룬 캄보디아 복합체 사례처럼, 사기·세탁·환전이 한 조직 안에서 분업되고 자체 스테이블코인까지 발행하는 수준에 이르렀습니다.

6. 탐지 기법 (방어 측)

A. Address Clustering

  • Common Input Ownership Heuristic (CIOH) — UTXO 모델에서 한 트랜잭션의 input 주소들은 한 사람이 통제한다는 휴리스틱.
  • Change Detection — 거스름돈 주소 식별.
  • Deposit Heuristic — 거래소의 consolidation 패턴을 이용한 클러스터 식별.

B. Attribution

클러스터를 알려진 엔티티(거래소·믹서·제재 대상)에 연결. 라벨 정확도의 공개 벤치마크는 없고, 감독기관도 분석도구가 실소유자를 "may not be able to identify"라고 인정합니다(NYDFS 2022-04-28).

C. 온체인 이상 패턴(anomaly) 탐지

  • Peel chain 패턴, 믹서 사용 패턴, 시간대 패턴
  • 룰 기반 + 머신러닝 결합
  • 용어 주의: 한국 법률에서 "이상거래"는 가상자산이용자보호법 §12의 불공정거래 우려 거래를 뜻합니다. 온체인 분석 맥락에서는 "이상 패턴(anomaly) 탐지"라고 부르는 편이 혼동이 없습니다.

D. Cross-chain Tracing

  • 브리지 입출금 매칭, 시간·금액·메타데이터 짝짓기
  • 공통 벤치마크가 없어 연구 간 수치 비교 불가(§2-C)

E. Exposure (노출도)

한 주소가 직·간접으로 믹서·제재 대상·도난자금에 닿는지를 나타내는 지표. 규범 근거는 FATF 2021 para 277~278 "extend beyond the immediate transaction". 홉 수 상한·감쇠 방식을 공개한 벤더는 없으므로 "N hop 안"이라는 고정 기준은 회사 정책의 선택입니다.

기술적 정밀화

Peel Chain 탐지 쿼리 예시 (SQL, UTXO 기준 — 임계값은 설명용 가정이며 근거 있는 기준값이 아님):

WITH chain AS (
  SELECT tx_hash, FROM_address, TO_address, amount,
         LAG(amount) OVER (PARTITION BY FROM_address ORDER BY block) as prev_amount
  FROM utxo_transactions
  WHERE block_time > NOW() - INTERVAL '30 days'
)
SELECT * FROM chain
WHERE amount < prev_amount * 0.05  -- 예시 임계값
  AND prev_amount > 10000000       -- 예시 임계값
ORDER BY tx_hash;

정확도에 대한 주의: "CIOH는 정확도 X%" 식의 단일 수치는 인용 가능한 근거가 없습니다. Möser & Narayanan (Resurrecting Address Clustering in Bitcoin, arXiv 2107.05749 / FC 2022)은 초록에서 "current techniques rely on heuristics that have not been rigorously evaluated or optimized" 라고 지적합니다. 실무 함의는 정확도 숫자가 아니라 클러스터 붕괴(cluster collapse) 위험입니다. 휴리스틱이 잘못 병합하면 무관한 엔티티가 한 클러스터로 뭉치고 그 위의 위험 점수가 통째로 오염됩니다.

실무 포인트

벤더 점수는 산정 방식이 비공개라 벤더마다 다른 결과를 냅니다. 같은 주소 샘플을 여러 벤더에 넣어 출력 일치율을 직접 재는 것이 유일한 비교 방법입니다(../7-vendors/vendor-benchmark.md).

7. 탐지의 한계

  • Privacy coin: Monero는 2023년 패치 이후 신규 거래에 대한 공개 휴리스틱이 무효
  • Off-chain trade: 거래소 내부 이체는 외부에서 안 보임
  • 새 믹서·브리지: 라벨링 전까지 탐지 어려움
  • Adversarial behavior: 무작위 금액·시간으로 패턴 회피
  • 벤치마크 착시: 템플릿 기반 이상 주입 벤치마크는 모델 강건성을 과대평가한다(TransXion, KDD '26)(arXiv 2604.17420)
  • 법적 제한: 다른 회사 고객 정보 접근 제한
  • 주소만으로 상대 VASP를 완전 식별하는 기술적 수단은 없다(FATF 2021 para 197(a))

Peel Chain 탐지 (RF-T1 계열):

def peel_chain(addr, depth=20):
    chain = []
    curr = addr
    for _ in range(depth):
        outs = get_outputs(curr)
        if len(outs) != 2: break          # peel 특징: 출력 2개
        small, large = sorted(outs, key=lambda o: o.value)
        if small.value / large.value > 0.3: break  # 예시 비율
        chain.append(curr)
        curr = large.to_addr
    return len(chain) >= 5                # 예시 길이

Pass-through 탐지 (RF-T4):

def pass_through(account, window_minutes):
    deps = deposits(account, window_minutes)
    wds = withdrawals(account, window_minutes)
    traded = trades(account, window_minutes)
    return deps and wds and not traded and sum(w.amount for w in wds) >= 0.9 * sum(d.amount for d in deps)

1. DeFi (Decentralized Finance)

정체성

DeFi는 중개자 없이 스마트컨트랙트가 lending·swap·derivatives를 처리하는 금융 인프라입니다.

용어: - TVL (Total Value Locked) — 프로토콜에 예치된 자산의 총 USD 환산 가치. - AMM (Automated Market Maker) — 알고리즘이 자동으로 가격을 정하는 DEX 구조. - DAO (Decentralized Autonomous Organization) — 거버넌스 토큰 홀더의 투표로 운영되는 조직.

항목 이슈

FATF 기준 — 통제자 판정

FATF 2021 가이던스 para 67: "A DeFi application (i.e. the software program) is not a VASP under the FATF standards ... However, creators, owners and operators or some other persons who maintain control or sufficient influence in the DeFi arrangements, even if those arrangements seem decentralized, may fall under the FATF definition of a VASP where they are providing or actively facilitating VASP services."

식별 질문(para 93): 누가 이익을 얻는가, 규칙 설정·변경 권한, 운영 결정, 출범 주도, 사용자와의 지속 관계·데이터 통제, 서비스 중단 권한. 통제자를 식별하지 못하면 국가는 규제 VASP의 개입을 요구하는 등 완화책을 고려합니다(para 69)(FATF 2021 RBA 가이던스).

2026-07-21 「Targeted Report on Regulatory Challenges from Decentralised Finance」는 이 분석을 "updates and complements"하며 기능적·위험기반 접근과 통제 존재 판정을 권고했습니다. 가이던스가 아니며 기준 변경도 아닙니다(FATF DeFi 보고서). 7차 TU 각주 1은 DeFi를 세 갈래로 나눕니다.

한국의 DeFi 규율은 2단계 입법 진행 상황이 확인되지 않아(보고서 부록 B #10) 여기 싣지 않습니다. 이전 판의 미국 입법·SEC 조치, MiCA의 "fully decentralized" 적용 제외 서술은 이번 근거 자료로 재확인하지 못해 삭제했습니다.

주요 DeFi 자금세탁 패턴

  1. Swap layering: 여러 토큰을 연쇄 교환해 출처 단절.
  2. Liquidity Pool 세탁: LP 입금 → 다른 자산으로 인출.
  3. Flash Loan 결합: 가격 조작 → 차익 인출 → 믹서.
  4. MEV 활용: 트랜잭션 순서 조작으로 자금 흐름 위장.

실무 포인트

DeFi 규제의 압력은 통제자에게 몰립니다. 거래소 입장에서 실무 질문은 "이 자금이 지나온 DeFi에 통제자가 있었나, 규제 VASP였나"이고, 답을 모르면 언호스티드 지갑과 같은 위험기반 처리를 적용하는 것이 FATF 2021 para 69와 정합합니다.

2. NFT (Non-Fungible Token)

AML 관점에서 NFT의 본질

NFT는 고유 자산 + 가격 자율 책정 + 즉시 글로벌 거래의 조합입니다. 거래 가격을 당사자가 정하므로 자금 이전을 "작품 대금"으로 위장하기 쉽습니다.

주요 패턴

패턴 설명
Wash trading 자기들끼리 사고팔아 가격·거래량 부풀림
Self-laundering 같은 사람의 다른 주소 간 매매
Trading mule 범죄 수익으로 NFT 매수 → 정당 자산화
Phishing 결합 가짜 민팅으로 지갑 탈취
Royalty 악용 로열티 수취 지갑으로 반복 거래 수익 집적

이전 판의 wash trading 비중(25~50%, 45~60%)과 마켓플레이스별 정책 변경 서술은 이번 근거 자료로 재확인하지 못해 삭제했습니다.

FATF 입장

FATF 2021 가이던스 para 53: NFT는 "generally not considered to be VAs"이지만 결제·투자 용도로 실사용되면 VA가 될 수 있고, "assets that do not qualify as VAs should not be presumed to fall outside the scope of the FATF Standards"(para 50)입니다. 하나의 자산이 VA와 금융자산을 동시에 겸하지는 않습니다(para 51).

한국의 NFT 가상자산 해당 여부 판단 기준은 이번 근거 자료로 재확인하지 못했습니다. 이전 판의 "2024-06 FSC 가이드라인" 세부 서술은 원문 확인 전까지 ../2-regulations/korea-fiu-act.md를 참조하세요.

실무 포인트

NFT 마켓플레이스를 운영하거나 NFT 대금이 거래소로 들어온다면, 기능 기준(결제·투자 용도인가)으로 VA 해당성을 판단한 근거를 남기세요. 판단 기준이 기능적이라 사례마다 결론이 바뀔 수 있습니다.

3. Privacy Coin

대표 코인과 기술

코인 기술 추적 가능성 (공개 연구 기준)
Monero (XMR) Ring Signature + Stealth Address + RingCT 2019~2023 지갑 버그("10 Block Decoy Bug" 등)·P2Pool·Mordinal 휴리스틱은 대부분 고정밀. 2023년 초 패치 이후 신규 거래에는 무효(arXiv 2408.05332)
Zcash (ZEC) zk-SNARK shielded transaction shielded 사용 여부에 따라 다름

기술 원리 한 줄 요약

  • Ring Signature — 여러 후보 서명자 중 실제 서명자를 숨김.
  • Stealth Address — 받는 주소를 거래마다 새로 생성.
  • RingCT — 금액도 암호화.
  • zk-SNARK — 거래 유효성만 증명하고 내용은 숨김.

규제

  • EU AMLR(2024/1624) 제79조: CASP가 익명성강화코인을 포함해 거래를 익명화·난독화하는 계좌를 보유·취급하는 것을 금지. 2027-07-10 적용 예정(enacted-not-in-force)(EUR-Lex).
  • FATF Red Flag RF-A1·A2: 수수료를 감수한 AEC 사용, 투명 체인 자산 → 거래소 → 즉시 AEC 전환(FATF Red Flag).

이전 판의 국가별 상장폐지 연도(한국 2021, 일본 2018)는 이번 근거 자료로 재확인하지 못해 삭제했습니다.

차폐 풀(privacy pool)의 정량 측정

2026년 연구는 "추적 불가/가능" 이분법 대신 수치로 측정합니다. - Railgun: 출금의 17.65%가 입금과 하나로 연결, 중위 익명성 손실 3.42비트(arXiv 2606.25926) - Railgun·Hinkal unshield 186,356건: 공개 토큰 제약만으로 평균 익명성 집합 40.1~59.0% 감소(arXiv 2608.22987) - Railgun PPoI 스크리닝은 오프체인에서 수행되며, 브로드캐스터는 PPoI를 요구하지만 사용자 직접 제출 거래는 검사를 건너뛴다(B)(L2BEAT)

실무 포인트

Privacy coin을 취급하지 않는 거래소에서도 위험은 진입·탈출 순간에 있습니다. 해외에서 AEC를 쓴 뒤 투명 체인 자산으로 바꿔 입금하는 흐름은 RF-A2의 역방향이며, 입금 주소의 직전 경로 노출을 봐야 합니다.

4. Cross-chain Bridge

정체성

A 체인 자산을 잠그고(lock) B 체인에서 wrapped 토큰을 발행. 환원하려면 B에서 소각 → A에서 해제.

AML 관점

  • Layering 인프라 — 체인 간 끊김.
  • 7차 TU: DPRK가 탈취 자금을 브리지·언호스티드 지갑·OTC로 세탁하고, RPC 노드·멀티시그 공급자 같은 제3자 인프라를 공격한다(para 33).
  • 추적 연구: 12개 브리지 양방향 F1 91.75%(ABCTracer), 5개 브리지 F1 0.9746(ConneX), Ethereum–Polygon 입금 매칭 93.04~99.65%·출금 67.55~92.78%. 브리지 집합·정의가 달라 수치 비교 불가(arXiv 2504.01822; arXiv 2511.01393; arXiv 2504.15449).

이전 판의 브리지 해킹 손실 표는 이번 근거 자료로 재확인하지 못해 삭제했습니다.

실무 포인트

출금 주소가 브리지 컨트랙트라면 다음 홉을 추적할 수 있는지가 관건입니다. 추적이 끊기면 그 시점 노출은 사실상 unknown이므로, 금액·고객 위험과 결합해 판단합니다. 이전 판의 "모든 브리지 출금에 자동 STR 후보 큐잉"은 근거 있는 업계 관행이 아니어서 삭제했습니다 — STR은 의심 판단의 결과이지 경로 자체의 자동 산출물이 아닙니다.

5. MEV · Flash Loan · Rug Pull · 기타

MEV (Maximal Extractable Value)

블록 생성 시 트랜잭션 순서 조작으로 얻는 이득. Sandwich attack은 가격 조작 유형입니다. 2026 연구는 제재 주소가 동결 발효 전 순서 선점으로 자금을 빼는 "Sanction-Evasion MEV"를 측정했습니다 — USDT 제재 주소의 7.3%, USDC의 18.7%가 동결 발효 전 전액 인출(arXiv 2603.27739).

Flash Loan

담보 없이 한 트랜잭션 안에서 빌리고 갚는 대출. 가격 조작 → 차익 추출 → 믹서로 이어질 수 있습니다.

Rug Pull

  • SoK(ISSTA 2025): 35개 rug pull 유형(9개 신규), 13개 탐지 도구 커버리지 25.7~62.9%, 복합 기법 rug pull에서 성능 급락(ISSTA 2025).
  • rug pull의 정의 자체가 복수(TVL 급감 기반 vs 거래 유휴 기반)이고, 벤치마크 데이터 누수가 탐지 성능을 부풀린다는 지적이 있습니다(academic 도시에 P-042·P-043).

LST · Restaking

자산이 staking 토큰으로 감싸지고 또 감싸지면 자산 형태가 바뀌어 layering에 쓰일 수 있습니다. 이전 판의 "2025년 부상한 신종 유형", 벤더별 LST 모듈 출시 서술은 근거가 확인되지 않아 삭제했습니다.

용어: - LST (Liquid Staking Token) — staking 증표 토큰. - LRT (Liquid Restaking Token) — LST를 다시 restaking하고 받는 토큰.

💼 실무 현장 (Industry Reality)

회색지대에서 선을 긋는 기준

공개 근거로 쓸 수 있는 기준은 다음 셋입니다.

  1. 통제자 기준 (FATF 2021 para 67·93): 경유한 DeFi에 통제자가 있으면 그 통제자를 상대 VASP로 보고 실사한다.
  2. 기능 기준 (para 53): NFT·토큰이 결제·투자 용도로 쓰이면 VA로 다룬다.
  3. 노출 평가 (7차 TU 권고 6-iv): 프로토콜·브리지·믹서·크로스체인 도구 노출을 평가한다.

이전 판의 "한국 4대 거래소 정책 표"(DeFi 입금·브리지 출금·LST 상장·Tornado 차단), 글로벌 거래소별 DeFi 대응, Risk Score 80/50 기준의 "한국 VASP 실제" 판정 플로, 마켓플레이스·거래소 NFT 사업 변화는 공개 근거가 없어 삭제했습니다.

자주 나오는 오해

  • "DeFi는 규제 불가니 우리 책임 아님" — CEX가 DeFi 경유 자금을 받는 순간 그 자금은 우리 거래모니터링 대상이다. 그리고 DeFi 통제자는 VASP가 될 수 있다.
  • "NFT는 예술품이라 AML 무관" — 기능 기준으로 VA가 될 수 있다.
  • "Monero는 한국에서 안 다루니 리스크 없음" — 해외에서 AEC를 쓴 뒤 투명 체인 자산으로 바꿔 들어오는 흐름이 리스크다.
  • "Tornado Cash는 해제됐으니 정상" — 형사 절차는 별개였고(2025-08-06 Storm 유죄 평결, B), 제재 기간 중에도 보안사고 자금의 다수가 Tornado Cash를 거쳤다(arXiv 2507.11721).

7. 스테이킹 서비스의 AML 함의

7.1 Staking이 왜 AML 문제가 되나

Staking: PoS 블록체인에서 코인을 묶어 네트워크 검증에 참여하고 보상을 받는 것.

VASP가 제공하는 유형: - Native Staking: 고객 자산을 validator에 위임 - Liquid Staking: 스테이킹 증서(LST) 발행 - Pooled Staking: 소액 보유자 대상 풀

7.2 AML 판단 논점

  • 보상이 자금원천 판단에 어떻게 들어가는가: 보상 자체보다, 스테이킹을 경유한 자금 흐름이 출처를 흐리는지가 문제다.
  • LST를 별도 자산으로 볼 것인가: 별도 가격·유동성을 가지므로 거래모니터링·트래블룰 대상 자산 목록에 포함할지 결정해야 한다.
  • Unstaking 대기 기간: 자금이 묶인 상태에서의 조사·동결 대응 절차.

7.3 규제 동향

  • EU AMLA는 2026-10-07 MiCA 재검토 AML 우선과제에 스테이킹·대출을 포함했다(AMLA).
  • 한국의 스테이킹 관련 정책 진행은 이번 근거 자료로 확인되지 않았다.

8. NFT 로열티 악용 — 숨은 typology

8.1 로열티란

2차 시장 거래 시 원작자가 일정 비율을 받는 구조. 마켓플레이스·컨트랙트 수준에서 집행됩니다.

8.2 악용 메커니즘

  1. 컬렉션 발행 + 높은 로열티 설정
  2. 공모자 간 반복 거래(wash trading)
  3. 로열티 지갑에 대금 누적
  4. 표면상 "예술품 2차 거래" → 자금 이전 은폐

8.3 탐지 룰 예시 (설명용 — 임계값은 가정)

def detect_nft_wash_trading(trades):
    alerts = []
    for collection in group_by_collection(trades):
        # 1. 소수 거래자 집중도
        top_ratio = top_n_traders_volume(collection, n=10) / total_volume(collection)
        if top_ratio > POLICY_CONCENTRATION:
            alerts.append("Concentrated trading")
        # 2. 동일 주소쌍 반복 거래
        for pair in address_pairs(collection):
            if pair.trade_count >= POLICY_REPEAT and pair.value_cycle_ratio < POLICY_CYCLE:
                alerts.append(f"Wash trading pair: {pair}")
        # 3. 로열티 수취 지갑의 유출 흐름
        if suspicious_outflow(collection.royalty_wallet):
            alerts.append("Royalty wallet outflow")
    return alerts
