# ADR-0002 · 이중시간(bitemporal) 모델 채택

- **상태**: 채택 (2026-07-30)
- **관련**: [`../ontology/02-dynamic-layer.md`](../ontology/02-dynamic-layer.md)

## 맥락

규제 지식은 시간에 따라 변한다. 단일 시간축(유효기간만)으로 충분한지, 기록시간까지 필요한지 결정해야 한다.

이중시간은 스키마와 질의를 복잡하게 만든다. 그 비용을 지불할 가치가 있는가?

## 결정

**이중시간을 채택한다.** 모든 L2 레코드는 `valid_from/valid_to`(유효시간)와 `recorded_at/retracted_at`(기록시간)을 갖는다.

## 근거

세 가지 질문이 각각 다른 시간축을 요구하며, 세 번째가 결정적이다.

1. "2023-06 시점에 이 거래는 트래블룰 대상이었나?" → 유효시간
2. "2023-06 시점에 **우리는** 그것을 대상이라고 알고 있었나?" → 기록시간
3. "당시 우리 판단의 근거는 무엇이었나?" → 두 축 교차

3번은 감독 검사·감사 대응의 핵심이다. 과거 판단의 정당성은 **당시 알 수 있었던 정보**로 평가된다. 나중에 밝혀진 사실로 과거 판단을 재구성하면 방어할 수 없다.

추가로:
- 소급 시행 규정 처리
- 오류 정정 시 "언제부터 잘못 알고 있었는지" 파악
- 추정 통계의 사후 개정 추적 (이 분야는 이듬해 대폭 상향이 관례)

## 결과

- `STATE`, `FACT`, `METRIC` 이 4개 시간 필드를 갖는다
- **덮어쓰기 금지** — 정정은 항상 `retracted_at` 설정 + 새 레코드
- 질의 API 가 `as_of(T)`, `known_as_of(R)`, `as_of(T, R)` 세 형태를 지원
- 저장 용량 증가 (정정 이력 누적)
- 큐레이터 교육 필요 — "고치지 말고 새로 쓴다"

## 대안

- **단일 시간축** — 단순하지만 3번 질문에 답할 수 없다. 감사 대응 자료로서의 가치가 크게 떨어진다.
- **Git 이력으로 대체** — 기록시간을 커밋 시각으로 갈음. 질의가 불가능하고(Git 로그를 파싱해야 함), 배치 임포트 시 커밋 시각이 실제 인지 시점과 무관해진다.
