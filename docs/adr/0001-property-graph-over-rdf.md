# ADR-0001 · 프로퍼티 그래프를 RDF 대신 채택

- **상태**: 채택 (2026-07-30)
- **결정자**: 온톨로지 관리자
- **관련**: [`../ontology/04-node-edge-spec.md`](../ontology/04-node-edge-spec.md)

## 맥락

가상자산 AML 지식을 그래프로 표현하기로 했다. 표현 형식으로 RDF/OWL 트리플과 레이블드 프로퍼티 그래프가 후보다.

핵심 요구:
1. 엣지 자체에 **유효기간·확신도·출처·임계값**을 붙여야 한다 (예: "이 조문이 이 의무를 부과하며, 임계값은 100만원이고, 2022-03-25부터 유효하며, 근거는 이 문서다")
2. 경로 탐색 질의가 지배적이다 ("이 의무의 국제적 뿌리를 거슬러 올라가라")
3. 큐레이터가 YAML 을 직접 손으로 편집한다

## 결정

**레이블드 프로퍼티 그래프**를 채택하고, RDF 는 내보내기 형식(JSON-LD)으로만 지원한다.

## 근거

| 요구 | RDF | 프로퍼티 그래프 |
|---|---|---|
| 엣지 속성 | reification 또는 RDF-star 필요 → 트리플 수 3~5배 증가 | 네이티브 |
| 경로 질의 | SPARQL 속성 경로, 가변 길이 표현 번거로움 | 자연스러움 |
| 사람 편집 | 트리플 나열은 사람이 읽기 어려움 | YAML 블록으로 직관적 |
| 추론 | OWL 추론기 사용 가능 (장점) | 직접 구현 필요 |
| 상호운용 | 표준 (장점) | JSON-LD 내보내기로 확보 |

RDF 의 장점인 추론은 이 도메인에서 활용도가 낮다. 규제 지식에서 자동 추론은 위험하다 — "A 국이 FATF 권고를 이행했으므로 A 국에 X 의무가 존재한다"는 추론은 실제로 자주 틀린다. **이행의 충실도(fidelity)가 부분적이거나 이탈적인 경우가 흔하기 때문**이다. 그래서 관계는 추론이 아니라 증거로 확정한다.

## 결과

- 엣지에 `qualifiers`, `valid_from/to`, `evidence` 를 직접 부착
- JSON-LD·SKOS·PROV-O·STIX 매핑을 내보내기 계층에서 제공
- OWL 추론 기능은 포기. 필요한 추론은 빌드 단계 규칙으로 명시적 구현

## 대안

- **RDF-star** — 엣지 속성 문제를 해결하나 도구 지원이 아직 고르지 않고, 큐레이터 편집성 문제는 남는다.
- **관계형 스키마** — 유연성 부족. 새 관계 유형마다 테이블 변경 필요.
